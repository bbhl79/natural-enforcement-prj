## 一、范围与前提

- 法域：土地（`land`）。
- 主线：线索登记 → 核查 → 分派 → 立案 → 调查 → 审理（含法审）→ 决定 → 送达 → 执行 → 结案。
- 角色群体：内勤、经办、行政审核、行政审批、法制审核，对照 `fixtures/identities/`。
- 不覆盖：听证、集体讨论（样例另设待权威示例）、移送、中止/终止的独立环节化（列为钉死点）。

## 五、待权威示例：集体讨论 `collective`

- 环节：重大复杂案件集体讨论。
- 输入：审理记录、法审意见。
- 产出：集体讨论记录。
- 协作关系：行政审批主持，法制审核列席。
- 法规出处链：**无**。触发阈值与上位法条款本草案未查证，不臆造。
- 角色依据：法制审核（`legal-st`）、行政审批（`approve-hq`）。
- 状态：**待权威**。只产决策票（`labels: ['needs-triage']`），不进实现方向，不计入对账缺口。

## 六、待主管钉死事项

1. 环节命名与粒度：中止/终止是独立环节，还是调查与审理之间的状态（当前按后者）。
2. 送达期限的上级法条款未查证，须补出处后入链。
3. 集体讨论的触发阈值与出处（见第五节）。
4. 审理与法审是否合并为一个环节（当前合并展示，呈批链分开）。
5. 核查与立案之间是否需要独立的「责令停止违法行为」出口（`doc_002` 附录 E 第 1 项，本草案未入表）。

    nodeId: 'filing',
    legalBasis: [{ documentCode: 'doc_002', articleNo: '2.6' }],
    roleBasis: ['经办', '行政审核', '行政审批'],
  },
  { nodeId: 'collective', legalBasis: [], roleBasis: ['法制审核'] },
]);
// filing → ok；collective → pending-authority，附 needs-triage 决策票草案
// admittedNodeIds 只返回 ['filing']，collective 不进实现方向
