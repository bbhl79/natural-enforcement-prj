## 允许的差异

- blocked：原型「在职人员」一条写「请先把他们调岗到其他机构，或停用相应人员」。#105 D4 规定已停用人员未结束的任职也拦停用，停用人员不结束任职，照做仍会被拒，所以实现只写「请先把他们调岗到其他机构。」——**工程稿，随 v0.5 定稿**（PR #144 ❓❓ 请确认）。
- blocked：原型同一条末尾的「查看人员」链接指向人员列表（P5），人员列表页还没有做（不在本票），本票不出这个链接，人员票接上。
- 左导没有「人员」：`personnel.profile.read` 还没进名册（同 #123）。
- confirm：见上，背景里选中的是五山，树上五山不带「已停用」，树卡片计数为「1 个已停用」。
- 服务端拒绝（含「本机构还有 N 条未办结的线索或案件……」）显示在确认弹窗顶部的红色横幅里，原型没有这一状态的图，由前端单测与集成测试覆盖。四种拒绝的可读原因、没有可读原因时的固定句「这个机构暂时不能停用，请刷新后查看原因。」都是**工程稿，随 v0.5 定稿**。
- 界面上不显示操作码和原始原因码（SCREENS.md 通用检查）：横幅只显示服务端的可读原因或固定句，前端单测断言不回落到 `reason`。
