# #132 截图对照（口令历史不重复：P2 改密被拒、P6 重设初始口令、P7 重设确认与被拒）

- 规格：Chrome headless（zenika/alpine-chrome 124），视口宽 1440，整页截图，2026-10-19（UTC+8）。
- 本目录 `<状态>.png` 是实现截图；`compare/<状态>.png` 是对照图，左边为原型 v0.4（`frontend/prototype/admin-console/screens/`），右边为实现，缩到一半大小。
- 做法：与 #127/#130 的「模拟接口驱动构建产物」不同，本票改用仓库自身组件做服务端渲染出整页 HTML，再截图。原因：卡片页与被锁人员页的列表数据经 `<Await>` 延迟到达，静态渲染拿不到已解析的列表，而弹窗是纯渲染组件、状态可由测试直接给定。具体做法：应用壳（`AppShell`）+ 页面主区（`PersonnelCardView`、`LockedPersonnelView` 与各自的面包屑、页头）按会话操作码直接组装，弹窗按状态传入；样式取 `dev build` 产物里的同一份 CSS；会话操作码取「名册 + 参照种子允许行」推出的真实清单（何静：经办 + 系统管理），含 `personnel.password.reset`。人物与行数据沿用原型 P6、P7 的数据（他人卡陈晓宁 TH0315、被锁四行王芳/张敏/周敏/陈立）。渲染脚本与截图驱动是接力期的一次性工具，不入库；五个状态键的可见文本另由前端单测逐字断言。
- 本票出 5 张 v0.4 状态键：`P2-forcedReused`、`P6-resetpw`、`P6-resetpwReused`、`P7-resetConfirm`、`P7-resetDenied-reused`。其中 `P7-resetDenied-reused` 由 #127 明确留给本票；`P6-resetpw`、`P6-resetpwReused` 由 #130 明确留给本票；`P7-resetConfirm` 重截，补上 #127 记为允许差异的口令要求末句「不能与对方最近 5 次使用过的口令相同」。
- 逐张差异说明：
  - P2-forcedReused：琥珀色「你要打开的页面需要先完成改口令」横幅、「首次登录必须更换初始口令」说明、新口令框下红色单句「新口令不能与你最近 5 次使用过的口令相同，请换一个。」逐字一致；原型样板里「更换口令」按钮常置灰，实现按两栏是否填写决定，截图里当前口令为空故同样置灰。原型顶部灰色「样板状态」条不属于正式界面。
  - P6-resetpw：弹窗标题「为「陈晓宁」重设初始口令」、新的初始口令输入、提示句「要求同新建人员，另外不能与对方最近 5 次使用过的口令相同。」、「确认后：」三条后果、取消与确认重设（危险色）逐字一致；背景卡片的危险操作区含重设初始口令一行（本票补入），行序与提示句照原型。
  - P6-resetpwReused：输入框下红色单句「此口令不可用，请换一个。」，不列规则、不说明原因（ADR 0015 管理员侧不暴露历史命中原因）；提示句里的规则句保留，与原型 PW-9 一致。
  - P7-resetConfirm：弹窗 kv（工号、当前机构名）、口令要求六条含末句「不能与对方最近 5 次使用过的口令相同。」、「确认后：同时解锁；对方的全部会话都会结束，同时结束全部「记住我」；对方下次登录必须先改口令。」逐字一致；背景列表四行与解锁、重设初始口令两个按钮照原型。
  - P7-resetDenied-reused：输入框下红色单句「此口令不可用，请换一个。」，口令要求句保留，不出现 reused、不说明第几次；弹窗不关、行保留。允许差异：实现输入框为 `type="password"` 显示掩码点，原型为明文取值；掩码继承 #127 弹窗实现，是安全正向选择，可见文本仍逐字一致。
- 界面不露操作码与原始结果码：五个状态的可见文本由前端单测断言（`personnel.test.tsx`、`lockedPersonnel.test.tsx`、`loginSlice.test.ts` 的「不露操作码与原始结果码」用例），`data-reason` 只落在属性里。

  - 重设成功横幅（`data-notice="password-reset"`）：`已为「<姓名>」重设初始口令。对方的全部会话和全部「记住我」已结束，下次登录须先改口令。`（工程稿，取 P7 重设成功定稿句去掉解锁分句）。
