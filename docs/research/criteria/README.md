## 判据项字段

底稿正文是一个 `json criteria` 代码块。`document` 是法规级元数据，`items` 是判据项。

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 判据编号，格式 `CRIT-<域>-<序号>`。全库唯一，永不复用 |
| `article` | 是 | 条号。条号须能在原文快照中定位 |
| `interpretation` | 是 | `直译`、`推导`、`裁量` 三者之一 |
| `expected` | 直译与推导必填 | 机器可断言的期望值。裁量型为空 |
| `sourceValues` | 直译必填 | 期望值取自原文的哪个词。每个值必须是摘录的子串 |
| `derivation` | 推导必填 | 推导链，元素为同目录内的判据编号 |
| `consumers` | 是 | 消费方，格式 `仓库路径#符号`。用于把判据分到模块产物 |
| `status` | 是 | `active`、`objected`、`superseded` |
| `excerpt` | 直译与推导必填 | 原文逐字摘录。空白归一化后必须是快照的连续子串 |
| `acknowledgedDoubtful` | 条件必填 | 引用效力状态为「存疑」的文件时，写接受理由 |
| `note` | 否 | 冲突说明、适用限制 |

## 解释类型三分

- **直译**：期望值直接取自摘录。`sourceValues` 证明取值不是凭记忆写的。
- **推导**：组合两条以上直译判据得出。`derivation` 写出组合链，任何能读法规的人可复核。
- **裁量**：法规没有给出结论，只能拍板。不产出机器断言，只产出风险登记。

## 业务决策

`decisions.md` 登记没有法规出处的业务决策。代码里 `basis` 写 `业务决策:DEC-<序号>` 时，该编号必须在本文件内。

| 字段 | 必填 | 含义 |
|---|---|---|
| `expected` | 否 | 消费方机器形态的期望值（规则键、天数、代码集合等）。供反向校验读取，不是法规断言 |

## 校验

```bash
node tools/generate-review-criteria.mjs --check
./dev lint criteria
```

`--check` 的八条断言：

1. 原文快照在场，sha256 与底稿相符。
2. 每条摘录是原文的逐字连续子串（空白归一化后）。
3. 条号能在原文中定位。
4. 文件编号命中文件表，效力状态非已废止；存疑须写接受理由。
5. 施行日不晚于今日，或标明尚未施行。
6. 裁量型不得带期望值。
7. 推导型必须有推导链，引用的判据编号都在同一底稿内。
8. 产物与底稿逐字节一致。

## 入库原文的版权

原文快照只收法律、法规、规章与国家机关的规范性文件。这些文件依《中华人民共和国著作权法》第五条不受著作权保护。快照保留官方公布文本，不做改写。
