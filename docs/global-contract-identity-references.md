# 全局契约：标识、主键与跨域引用关系骨架

- **出处**：wayfinder 票 [#16 全局契约：标识、主键与跨域引用关系骨架](https://github.com/bbhl79/natural-enforcement-prj/issues/16)（根Map 契约层）。
- **效力**：本文件是「粗细分两层」契约的**粗层**（根Map 只定标识、主键与引用关系）。§5 边界清单内的事项，5 个业务子Map 与 1 个架构工程子Map **只能细化字段，不得改动形状**。
- **输入**：全部实体关系来自用户故事；已关闭票 #17（数据责任边界）、#35（法域与多值引用结构）、#41（一事 vs 数事承载）、#21（模块边界）为本契约的前提；#18（不可篡改与追加式全局策略）待关闭，本契约引用其策略但不重复定义。

## 1. 标识总则

1. **所有实体一律全局唯一、不可复用、无业务含义的技术主键**（如 ULID）。
2. **业务编号**（案号、文号、线索编号等）是与主键**分离**的受管字段：编号可换、可补、可有规则，但**永不充当引用键**。
3. 跨域引用一律使用技术主键，不使用业务编号。
4. 编号规则本身归各子Map 定字段细节，本契约只钉「编号 ≠ 主键、引用不用编号」。

## 2. 实体清单与标识规则

### 2.1 业务实体（案件聚合域）

| 实体 | 标识规则 | 写权归属（#17） | 说明 |
|---|---|---|---|
| 线索 | 全局唯一主键 | 立案前归线索登记域；**立案是权属转移点**，立案后并入案件聚合（一体流转），线索实体保留为只读溯源端点 | 独立实体；持有空间对象；记录渠道、法域 |
| 录入批次 | 全局唯一主键 | 线索登记域 | **留痕单元**，非聚合实体；批量录入必挂，单条录入可空 |
| 线索处置记录 | 全局唯一主键 | 线索登记域 | **追加式，不修改**；类型含立案关联／不立案／移送／其他关联／解除；「解除」= 追加解除记录，原记录永久保留 |
| 案件 | 全局唯一主键 + 分离的案号 | 案件聚合 | 单一权威源（#17） |
| 违法记录（= 一个行为） | 全局唯一主键 | 案件聚合 | 定义与承载见 #35、#41；一个行为在任何聚合方式下不得拆散 |
| 处罚决定书 | 全局唯一主键 | 案件聚合 | 案件可一对多（#35） |
| 期限单据 | 全局唯一主键 | 系统（期限/预警模块） | 侧链上单据、事件驱动、**人不可手改**（#17）；锚形状见 §3.4 |
| 文书 | 全局唯一主键 | 案件聚合 | 案件内的**流程产物**；成文即冻结模板版本快照（§3.5） |
| 卷宗 | **不另发主键**——逻辑身份即案件标识（贯彻 #17「非独立数据」） | 案件聚合 | 单一逻辑身份；见 §3.6 |
| 归档代次 | 卷宗内的封存版本记录（有全局唯一标识，属卷宗聚合内） | 案件聚合 | 定型即第 N 次归档；归档后补正／受控重开 = 新代次追加 |
| 材料 | 全局唯一主键 | 案件聚合 | **append-only，不物理删除**；删改 = 标记作废 + 留痕（谁、何时、原值）；标识不回收不复用；业务引用见 §3.6 |
| 线索空间对象 | 全局唯一主键 | 线索登记域（立案后随线索只读） | 逻辑对象，可含 N 个几何部件；见 §3.7 |
| 案件空间对象 | 全局唯一主键 | 案件聚合 | 逻辑对象，可含 N 个几何部件；回指来源线索空间对象；见 §3.7 |

## 3. 关键引用关系与基数

### 3.1 线索 ↔ 案件（经线索处置记录）

```
线索 1 ──< 线索处置记录 >── 0..1 案件
```

- **线索 → 案件：0..N**（一条线索可拆立多个案件）。
- **案件 → 线索：1..N（强制）**。不存在无源案件：当场发现也是疑似违法，一律先登记线索再立案（含本机关自产线索，渠道标为自查/巡查/卫片）。立案时强制校验关联线索存在。
- 不立案、移送、建立关联、解除关联，全部是**线索处置记录**；每条处置记录挂接处置过程材料（核查报告、移送公文等），线索侧**不建独立卷宗实体**。
- 移送凭据入卷留痕并可关联线索（#10 已确认的规程要求）通过处置记录 + 材料承载。

### 3.2 案件 → 违法记录 → 决定书

沿用 #35 已定结构（此处仅索引，不重复定义）：案件 1..N 违法记录；案件 1..N 处罚决定书；决定书覆盖 N 条违法记录；案件法域集 = 违法记录法域的投影。

### 3.3 录入批次 → 线索

- **录入批次 1..N 线索**：一次批量录入 = 同一操作人、同一录入时间、同一法域、同一空间数据文件。
- **批量录入约束：必须同法域、单一几何类型**（点面不混）；空间数据含 100 个要素即生成 100 条线索。
- 批次是纯留痕锚点（时间、操作人、来源文件标识、法域、要素数），不改变逐条核查、逐条分派的业务粒度。

### 3.4 案件 → 期限单据

- **案件 1..N 期限单据**。
- 期限单据的锚 = **案件（强制）+ 程序节点类型 + 进入次序号**。
- **进入次序号**用于区分「调查环节第 1 次进入」与退回补正后的「第 2 次进入」，是回流继承的结构性前提；起算、中止、不计入期间、继承规则本体归 #29。

### 3.5 案件 → 文书 → 模板版本

- **案件 0..N 文书**（实务上任何案件出口都产生文书；必需性清单归 #32）。
- 文书是案件聚合内的**流程产物**，非独立案件对象。
- **文书 → 模板版本：0..1**（当事人提交件等非模板文书为空）；成文瞬间冻结「模板版本标识 + 版本内容快照（哈希）」，旧案件天然追溯当时生效版本，模板事后改版不回溯。

### 3.6 案件 → 卷宗（逻辑身份）→ 归档代次 → 材料

```
案件 1 ── 1 卷宗（逻辑身份 = 案件标识）
卷宗 1 ── N 归档代次（定型一次 = 一个代次）
卷宗 1 ── N 材料（生长期间持续追加）
```

- **卷宗单一逻辑身份**，不另发主键；「多次归档」表达为卷宗内的归档代次，不是新卷宗实体。
- **自然生长**：立案后材料随各环节流转持续归入；未定型前主办人可删改材料，但一律**标记作废、追加留痕**（谁、何时、原值），不物理删除。
- **定型 = 主办人显式确认 + 审批留痕 + 锁定**；定型即产生一个归档代次。定型后只能走 #17 受控重开（须审批、旧版本永久保留、新版本追加生效）或送达后的法定更正；归档后补正 = 新代次追加（同 #13「修正形成新版本或补充记录」）。
- **材料 0..1 回指产生它的来源业务记录**（文书标识、审批记录标识、核查任务标识等）；归档时回指目标的内容快照一并固化。材料不嵌入内容副本，内容是引用 + 快照。
- 线索处置材料挂线索处置记录（§3.1）；该线索日后立案的，处置记录随案件卷宗可见。

### 3.7 空间对象（线索空间对象、案件空间对象）

- **线索、案件各持有 1..1 空间对象**（逻辑对象，可含 N 个几何部件，部件各带几何类型）。录入即必填 vs 核查前补齐的**必填时机**归 #10 字段细化；结构权属 1..1。
- **几何类型由法域决定：土地、矿产 = 面；测绘地理信息、国土空间规划 = 点。** 线索侧同规则。
- **多部件**：一个案件多宗地块、一条线索多个点位 = 一个空间对象含多个几何部件；跨法域混合（土地面 + 测绘点）允许，部件各自带类型。
- **坐标口径**：系统内全局统一 **CGCS2000**；原始来源坐标按来源保留为属性（不丢弃，便于与来源单位核对）。
- **两个长期图层**：线索图层、案件图层，有联系但各自独立维护。
- **案件空间对象 0..N 回指来源线索空间对象**（核查修正后保留原始引用可比对）；**线索空间对象 0..N 被案件空间对象引用**（一条线索可拆多案）。
- **修正规制**：与材料同规制——定型前主办人可改、改动留痕（旧版本保留）；定型后只能受控重开或法定更正。

### 3.8 「谁做的」→ 身份/组织

- 所有「谁做的」记录（承办人、审核人、会办人、审批人等）**只引用稳定的人员标识**；当时的机构、岗位由**任职记录**（带起止）还原。
- 两级分派（单位→人）、主办协办固定与换人审批，按 #10 已确认输入执行，引用形状不变。
- 机构改名：**单据只存机构 ID，展示按单据时点渲染当时生效的名称版本**——旧名可查、新名可用、新旧名经同一 ID 可追溯；人员姓名、岗位名称同理。失效标记与名称版本是正交的两件事。
- 涉密案件线下纸质不入系统（#17），系统中不存在涉密等级概念。

## 4. 全局模式（跨实体通用）

1. **版本化参考数据集 + 冻结快照**（#35 模式）：字典/规则类与身份组织类参考数据按版本或时间化管理；业务单据记**当时快照**，事后调整不回溯。适用于 §2.2 全部。
2. **追加式与标记作废**：处置记录、材料、删改留痕全部追加式；系统**不物理删除**业务记录。具体机制归 #18。
3. **默认锁定 + 受控重开**（#17）：案件聚合、材料、空间对象、定型卷宗均适用；须审批、旧版本永久保留、新版本追加生效、全程留痕。
4. **基础数据不可删除**：人员、机构、岗位只可标记失效，不可删除。

## 5. 效力边界清单

### 5.1 子Map 不得改动（本契约形状）

1. 实体清单（§2）与各实体写权归属（#17 矩阵）。
2. 全局唯一技术主键；业务编号与主键分离；引用一律用主键。
3. 线索独立实体；线索 0..N 案件、案件 1..N 线索（强制无无源案件）；处置记录追加式模式。
4. 期限锚 = 案件 + 程序节点类型 + 进入次序号。
5. 卷宗单一逻辑身份（无独立主键）+ 归档代次；材料全局标识、回指来源业务记录、标记作废不物理删、定型即锁定。
6. 文书 = 案件内流程产物；0..1 模板版本、成文冻结快照。
7. 空间对象线索/案件各 1..1、多几何部件、法域定几何（土地/矿产=面，测绘/规划=点）、CGCS2000 + 来源坐标保留、双长期图层、案件回指来源线索空间对象。
8. 「谁做的」引用稳定人员标识 + 任职记录还原当时身份；人员/机构/岗位不可删除只失效；名称版本化、单据只存 ID。
9. §4 全局模式四条。

### 5.2 子Map 可自行细化（字段层）

字段定义、业务编号规则、必填时机与校验细则、模板版本回退链、期限起算与继承规则（#29）、批次上传文件格式、状态机本体（#27）、完整性必需性清单（#32）等。

## 6. 新术语（供 #20 术语基线吸收）

线索处置记录、录入批次、归档代次、任职记录、名称版本、线索空间对象、案件空间对象、几何部件。

## 7. 表述澄清

#15/#21 中「案件聚合吞线索/卷宗/文书」的语境是**模块写权归属**，不是实体一体建模决定。本契约下线索是独立实体：立案前由线索登记域写、立案后作为只读溯源端点并入案件聚合——两者不冲突。
