# ADR：快照采集一致性机制（stat 括号 + 内容双读）与成立条件

- 日期：2026-11-25（v2：按复审意见纠正论证并更换机制）
- 状态：**已接受**（Lei Hu 于 2026-11-25 22:12（Asia/Shanghai）裁决：接受内容级
  完美往返（ABA）为已声明局限；不另开文件系统级机制票。#58 验收第二条在上述
  已声明局限下视为满足）
- 相关：#58（保证构建快照与运行镜像一致）、#23 Spec-工程基座 §3、
  docs/evidence/58-snapshot-immutable/

## 1. 三个不可互替的命题（论证纠正）

复审指出：此前把不同命题混为一谈。必须区分：

1. **镜像忠实于已采集内容**（image ≡ snapshot）：由构造保证——构建上下文是快照
   物化目录，采集后不再读活工作树；证据 `15-snapshot-consistency.txt`
   （快照哈希 ↔ 镜像内容逐字节对账）。**本命题成立。**
2. **采集内容对应一个真实的完整工作树状态**：采集机制的职责——窗口内任何
   写入若未被完美复原，必须被检出（重试或明确拒绝）；接受 ⟹ 捕获树等于窗口内
   某瞬时的工作树全量状态。**这是本 ADR 的主题。**
3. **多文件修改属于同一次业务更新**：例：用户先存 A（特性 X 的一半）再存 B
   （另一半），两次保存之间的快照是真实状态，但不是有意的逻辑单元。**任何文件
   系统机制都无法判定"业务更新边界"**——这是语义属性，超出 #58 与本层机制，
   明确不保证（属提交纪律/工具链范畴）。

此前错误：用命题 1 的证据（快照↔镜像对账）冒充命题 2 的证明；用"双采集相同"
冒充"曾同时存在"；把命题 3 的"混合"（业务不连贯）与命题 2 的"混合"（从未存在
的组合）混用。另纠正一处事实：**覆盖已有文件不一定更换 inode**（`>` 截断覆写
保持 inode）；**等长原地覆写后恢复 mtime 并不必然是恶意行为**（`rsync -a
--inplace`、部分构建工具即如此）——因此"非恶意写者不可检出"的辩护不成立，
该类写入必须被机制覆盖。

## 2. 决策：stat 括号（端点）+ 内容双读

```text
capture_once:
  files  = git ls-files -c -o --exclude-standard      # 枚举（失败 → die，不静默）
  stats1 = stat(files)                                 # 端点括号 A（mtime,size,inode,mode）
  pass1  = 分两批 git add（临时索引；批间为读取交错测试缝）→ manifest1 = ls-files -s
  pass2  = 全量重读（同一临时索引重置后 add -A）        → manifest2 = ls-files -s
  stats2 = stat(files)                                 # 端点括号 B
  接受 ⟺ manifest1 == manifest2 ∧ stats1 == stats2 ∧ 文件清单一致
  tree   = write-tree（pass2 索引）
capture: 最多 3 次；均不稳 → 明确拒绝（exit 4）；枚举/清单/写树失败 → die
```

**成立论证**：接受 ⟹ 每个文件的 (mode, blob) 在两遍全量读取间逐字节一致
（内容双读），且窗口两端 stat 一致（括号），且文件清单一致。因此窗口内任何
写入只有两种结局：被检出（重试/拒绝），或属于"完美往返"（内容+stat 在窗口内
完全复原）——后者的捕获内容即盘上内容（两遍读取均为该内容）。**mtime 恢复型
等长覆写**（改内容、复原 mtime/size/inode）在第一遍与第二遍读取之间产生内容差
→ 被内容双读检出（A/B 实证见 §5）。

**为什么 stat 括号仍需保留**（而非仅内容双读）：内容比对基于索引（各文件 add
时刻的 blob），文件在其 pass2 add 之后、窗口结束之前的写入不产生内容差；端点
stat 括号覆盖这一段（stat 可见写入）。二者互补。

**失败语义**（复审项一）：枚举（ls-files）失败 → die 4（非 git 仓库/索引损坏，
重试无意义）；add/读取失败 → 重试（多为窗口内文件消失的瞬态），3 次后拒绝；
stat 失败 → 瞬态重试、硬错误（无 GNU stat）直接传播；所有步骤显式检查返回码
——函数在 `$(...)`/`||` 上下文中 set -e 被抑制，不依赖其兜底；路径经数组传递
（空格/通配符安全），枚举 NUL 流不过 bash 变量（命令替换丢 NUL），空文件集合
显式合法。

## 3. 覆盖的写入者（成立条件）

以下写入全部被检出（重试或拒绝）：

- 原子重命名保存（vim/VSCode/JetBrains/sed -i）：inode+mtime 变 → stat 括号；
- 原地写/截断重写/追加：mtime+size 变 → stat 括号；若复原 mtime（等长）→
  内容差 → 内容双读；
- **等长原地覆写 + 恢复 mtime**（`rsync -a --inplace`、构建工具）：内容差 →
  内容双读（A/B 实证）；
- chmod（mode 变）：manifest 含 mode → 内容双读；
- 新建/删除/改名：清单复核 + manifest 差；
- 采集窗口内任意时刻的上述写入（含某文件 pass2 add 之后）：端点 stat 括号。

依赖的写入者行为：仅"写入会改变 (content, mode, mtime, size, inode) 中至少
一项，或留下内容差"——普通编辑器与构建工具的全部写入方式均满足；**不**依赖
写入者避免 mtime 复原。

## 4. 原理性残余（已声明局限，经裁决接受）

**完美往返（内容级 ABA）**：某文件在窗口内内容 X→Y→X 且 stat 复原——两遍读取
均为 X、stat 一致 → 接受。此类写入的捕获内容即盘上内容（两遍均为 X），但严格
的同时性论证在 ABA 下不成立（组合可能未同时存在）。**任何只读机制在原理上都
无法检出完美往返**（等价于要求感知反事实历史）；关闭它只能走文件系统级快照/
日志（btrfs/APFS 快照——WSL2 ext4 不可用；或 fanotify 阻断式监听——新宿主
依赖）。现实写入者（编辑器/构建工具）不在 ~100ms 窗口内做全内容往返。

**裁决（Lei Hu 于 2026-11-25 22:12（Asia/Shanghai））**：接受内容级完美往返
（ABA）为已声明局限；不另开文件系统级机制票。#58 验收第二条在上述已声明
局限下视为满足。

## 5. 验证方法（确定性，不撞概率）

- **A/B 对照**（证据 `16-ab-stat-only-vs-content-double-read.txt`）：同一读取
  交错注入（批次钩子，两个 mtime 恢复型等长覆写 G 先于 F），stat-only 变体
  接受从未存在组合 (G1,F2) 零重试（盲区实证）；生产实现（内容双读）检出并重试。
- **离线确定性测试**（devenv/test/snapshot-offline.test.sh，经 `snapshot_test_hook`
  测试缝在读取阶段内注入）：
  - S23 交替更新：已读文件被改 → 重试；最终接受完整当前状态；从未存在组合
    (a-v1,b-v2) 未被接受；
  - S24 空格仓库 + 空格/通配文件名：采集正确；窗口内修改含空格文件名被检出；
  - S25（项二反例）：两个 mtime 恢复型等长覆写交错 → 内容双读检出，接受完整
    新状态，从未存在组合 (G1,F2) 未被接受；
  - S26 失败传播：枚举失败/读取失败/stat 失败 → die 或重试后拒绝，无树输出、
    无成功状态；
  - S27 真实入口（严格模式）+ 空格文件名全链路。
- **真实引擎**：持续写入拒绝（`05`）、停止后重试（`06`）、构建期修改不泄漏
  （`06b`）——见 docs/evidence/58-snapshot-immutable/。
- **成本实测**：内容双读 = 两遍全量读取，本仓库（~2MB/200 文件）采集约
  100–200ms（原 stat 括号约 50ms），每次消费命令一次；WSL2 ext4 与 macOS
  APFS 均为本地卷，语义一致（macOS 经 coreutils gstat，白名单内）。

## 6. 跨平台说明

- WSL2：仓库须在 ext4 本地卷（9P/挂载盘（/mnt/c）的 mtime/inode 语义不保证——
  基座要求仓库在 WSL2 原生文件系统）。
- macOS：GNU stat 经 coreutils（`gstat`，白名单已有）；APFS 本地卷 inode/mtime
  语义满足；批次 pathspec 经 `--literal-pathspecs`（git ≥1.9，两平台一致）。
