# 锁与栈使用租约协调

- 状态：accepted
- 日期：2026-11-26
- 决策记录：Spec-工程基座（[#23](https://github.com/bbhl79/natural-enforcement-prj/issues/23) §4 并发语义）；实施票 [#61](https://github.com/bbhl79/natural-enforcement-prj/issues/61)；前置 [#59](https://github.com/bbhl79/natural-enforcement-prj/issues/59)（per-worktree 锁分派）与 [#58](https://github.com/bbhl79/natural-enforcement-prj/issues/58)（mkdir 锁原语与失效演练）

## 决策

同一 worktree 内用两态协调栈资源，跨 worktree 用机器级锁协调共享上游资源：

- **排他锁（写者）** `stack-<wt>.lock`：build / up / down / restart / web（up 与
  `--down` 路径）/ migrate / migrate:create。复合过程"检查新鲜度 → 构建 →
  启动/停止"从入口到退出整体持锁；migrate* 另取 `migrate-<wt>`（按 stack →
  migrate 顺序）。
- **共享租约（读者）** `stack-<wt>.lease/<pid>.<epoch>.<rand>/owner`：
  test / test:unit / verify / lint / typecheck / seed 的运行期。多个读者可并行；
  与写者双向互斥（读者遇排他锁等待 120s；写者遇活跃租约等待各自的锁超时）。
- **进入决策**由短临界区门 `stack-<wt>.gate`（mkdir 原子）串行化：读者在门下
  确认无排他锁后登记槽；写者在门下确认无存活租约后建锁。门只持毫秒级；门持有者
  带唯一 token（owner 第三字段），释放时校验 token、取得后复核 token——极端
  ABA 下失去门则撤销本次登记并重试，不把他人重建的活门当失效门删除。
- **失效处理**：锁目录/租约槽的 owner 记录 pid + 启动时间（租约另记槽名/门另记
  token）；失效判定用 `kill -0`，**不按超时清除**——慢构建/慢测试仍存活时锁与
  租约有效。owner 文件缺失或为空给 1s 宽限（写入窗口），宽限后仍无有效 pid 才
  判失效；失效锁/租约在下一次取得时清理（写者路径；读者登记路径也清理失效槽，
  避免只有读者时环境被死锁永久阻塞；读者路径还会清理失效排他锁）。
- **等待策略**：写者不得在测试中途拆栈/迁移/替换服务，等待超时后 **exit 6**，
  错误消息列出持有者 pid/启动时间/槽与修复线索；读者遇排他锁同样等待后
  exit 6。等待上限沿用各命令原锁超时（build 120s、up/down/restart/web 60s、
  migrate* 10s）。`DEVENV_LOCK_TIMEOUT=<整数秒>` 为测试/故障演练显式覆盖等待
  上限（日常不设）。
- **机器级锁**：lockgen（原有）与 prefetch（本票新增）跨 worktree 互斥，分别
  保护共享 lockgen 容器/标签与上游基础镜像拉取；两者不取栈使用租约——租约只
  协调 per-worktree 栈。prefetch 锁覆盖 `devenv prefetch` 的显式拉取；构建期
  `FROM` 触发的隐式拉取由引擎按内容寻址去重，不在本锁范围内。
- **可见性**：`devenv status` 报告锁目录条目与租约槽（`--json` 终值 `leases`
  字段）；stale 只标注、不清理（status 保持只读）。
- **不纳入租约**：exec/shell/logs。exec/shell 是透传调试通道，交互时长无界，
  纳入租约会让一次调试长期阻塞拆栈；down 可能中断调试会话，由使用者自行协调。

## 背景

- Spec 硬不变量：**启动不被打断 ≠ 测试不被打断**。测试/run 运行期持栈共享
  使用租约；`down`/`restart`/`migrate`/替换服务取排他意图时须等待活跃租约释放
  或拒绝（exit 6），不得在测试中途执行。多个隔离测试可并行，不强行串行化。
- #59 已把 stack/migrate 锁按 worktree 隔离；#58 已验 mkdir 锁原语与失效演练
  （T13–T15）。缺的是读写协调，以及机器级基础镜像拉取锁。
- 本票前：test/lint/typecheck/verify/seed 不持锁，`down` 可拆掉正在运行的测试；
  prefetch 无机器级互斥，多个 worktree 可同时拉同一上游镜像；`web --down`
  未持栈锁。

## 考虑过的选项

- **flock/原生读写锁**：拒绝。macOS 默认无 flock，宿主工具白名单不含；mkdir
  方案已在 #58 验证并跨平台成立。
- **共享计数文件**：拒绝。并发增减计数本身需要锁，且持有者失效判定困难。
- **读者也持排他锁**：拒绝。多个隔离测试被迫串行，违反"不强行串行化"。
- **写者优先（pending 标记阻止新读者）**：拒绝。实现复杂且对读者不公平；
  固定超时 + exit 6 已满足"等待或拒绝"，持续读者导致的写者饥饿以超时拒绝收尾
  （已声明限制）。
- **租约槽按命令名合并**：拒绝。同一命令的多个并发进程需要独立失效判定。
- **超时自动删锁/租约**：拒绝。违反 Spec——慢构建（慢测试）仍存活时不得误清。
- **exec/shell 持租约**：拒绝。交互时长无界，会长期阻塞拆栈。

## 后果

- 读者并行、写者等待或拒绝：测试运行期间 `down`/`restart`/`migrate`/替换服务
  不会执行到一半，测试环境不被拆；kill 持有进程后失效锁/租约由下一次取得清理，
  不永久阻塞环境。
- **已声明限制**：
  - **pid 复用**：owner 只按 pid 存活判定（与 #58 锁同口径）；pid 被无关进程
    复用时可能误判存活，以超时 exit 6 收尾，需人工确认。
  - **门 ABA 残余**：mkdir + 失效清理没有原子的 compare-and-swap。两个进程同时
    判定同一死门失效时，仍存在"清理后重建的活门被后到者误删"的窗口；本票以
    空 owner 宽限、token 校验释放/复核、清理前再读 owner 收窄窗口，并在失去门时
    撤销本次登记重试，但不声称完全消除。读写两侧的再次检查兜底实际后果（读者
    入槽后写者会看到槽并退让；写者建锁后读者会看到锁并退让），建议在高并发
    故障注入中继续观察。
  - **写者饥饿**：持续有新读者进入时，写者直到等待超时才 exit 6；不做写者优先。
  - **读者侧并发重建**：读者在共享租约下执行 `ensure_fresh_workspace`——"起栈
    阶段持栈排他锁完成后释放，转入共享租约跑测试"中的"起栈"由 `up` 承担；
    test/verify 不启动栈，只消费已起栈环境。其新鲜度重建在同一快照下内容寻址
    得到同一 image ID，运行绑定使用各进程自己的不可变 image ID（#58），状态文件
    last-writer-wins 且下一次命令重新核对——不声称状态文件写入是并发事务。
  - **调试通道**：exec/shell/logs 不持租约，拆栈可能中断调试。
- 跨 worktree 的不同栈互不阻塞；机器级仅 prefetch/lockgen。
- 证据：`docs/evidence/61-lock-lease/`（Windows WSL2 实机冲突矩阵、kill 持锁
  进程恢复、慢构建存活不被误清反例）；离线用例 T16–T21（锁库）与 I10–I15
  （per-worktree/机器级/真实入口）。
