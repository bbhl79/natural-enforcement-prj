# e2e 双轨生命周期机制：探索→复现单向毕业，缺陷记录文件化

- 状态：accepted
- 日期：2026-11-19
- 决策记录：[Grilling-e2e生命周期机制设计](https://github.com/bbhl79/natural-enforcement-prj/issues/10)

## 决策

e2e 体系由**探索轨道**（发现未知缺陷，不进 CI）与**复现轨道**（逐 PR 运行的确定性回归）组成，单向转换：探索→复现可**毕业**，反向禁止。毕业命令是复现轨道用例的**唯一合法写入路径**，由工具与制度双重保障。具体机制：

1. **状态机四站**：`reported`（过门禁、已登记）→ `graduated`（复现用例已入轨）→ `fixed`（修复确认，转常绿回归）；`retired` 终态（记录原因，用例移除，缺陷报告永久留档）。不设隔离态。
2. **事实源分层**：每缺陷一个 JSON 文件（`apps/e2e/defects/DEF-NNNN.json`，入库）是生命周期事实源；目录（`tests/repro` vs `tests/explore`）表达用例归属轨道；测试文件头只放缺陷链接，不复制状态；注册表是派生缓存，不入库，由校验器重建比对。缺陷记录永不删除（审计底线）。
3. **预期失败闭环**：毕业时缺陷未修，用例带 `test.fail()`（expected-fail），CI 判绿；修复后"预期失败却通过"使 CI 变红，`confirm-fix` 摘标记转 `fixed`。修复 PR 顺带复现用例时，允许跳过 expected-fail 直接以 `fixed` 毕业（fixImmediate 旁路）。
4. **毕业事务**：预检 → 转写 → **真跑一次**（未修复必须失败 / 已修复必须通过）→ 落账；任一步失败工作区全量还原。不可机械转写的缺陷（agent 会话、monkey）经 `tests/repro/_drafts/` 草稿区（CI 不收集）补完断言后转正。测试文件与缺陷记录必须在同一 commit 落地。
5. **防降级校验**（`devenv verify` 与 CI 同一校验器）：索引一致性（用例↔记录双向锁死）、注解纪律（`skip`/`fixme` 全禁、`test.fail()` 仅限 graduated）、编号连续无洞、diff 级检查（repro 删除/移动必须伴随退役）。v1 不做内容哈希。
6. **缺陷报告 schema**：zod 按引擎判别联合；`DEF-NNNN` 递增号（本地 max+1 取号，撞号 renumber 机械重排，CI 查唯一+连续）；证据只存 URI 不入库，靠 `replayCommand` 长期重建；`title`/`summary` + 录屏证据供人读（`devenv e2e defect show`）。
7. **复现用例统一收敛** `apps/e2e/tests/repro/`，Playwright runner，默认黑盒（API/UI）；仅 `packages/` 导出的纯函数允许白盒复现（`apps/api` 内部逻辑必须走 API）。
8. **命令面**：顶层 `devenv ci`（与 CI 逐字节同构：起栈→只跑复现轨道→拆栈）/ `devenv explore` / `devenv verify`（质量门+生命周期校验）；子命令 `devenv e2e report | graduate | confirm-fix | retire | replay | renumber | defect show|list`；全部 `--json` 输出、退出码枚举化。CI 只经 devenv 调用，靠独立 repro/explore 配置 + 目录约定自动生效，毕业不改任何 CI 文件。

## 背景

- 地图硬不变量 3 要求双轨单向由「毕业命令 + 校验工具化、制度化」保障；本 ADR 是该不变量的机制化。
- 约束：AI-Native（1 人 + 多 agent 并发 worktree、机器可解析输出、fail-fast）、devenv 唯一入口、基础设施容器共享 + 数据级隔离、`apps` 互不依赖（#9）。
- 依据：`docs/research/playwright-e2e.md` §2–§4（数据隔离、CI 模式、失败产物链）、`docs/research/exploratory-testing.md` §3–§4（五层引擎、缺陷工件、复现门禁量化依据、毕业转写）。

## 考虑过的选项

- **中央注册表（入库）为事实源**：多 agent 双写次次冲突、注册表与详情双账本漂移 → 拒绝；改为每缺陷一文件，注册表退化为派生缓存。
- **状态写在测试文件头注释**：毕业前测试文件不存在，reported 期缺陷无处安放；注释不可查询 → 拒绝。
- **复现用例按发现层散落各包**（unit/api/ui 分家）：生命周期机制需覆盖多 runner 多目录，防降级校验器跨包扫描，且 e2e 无法合法 import `apps/api` 内部实现 → 拒绝；统一收敛 `apps/e2e`（packages 纯函数白盒为唯一例外）。
- **毕业与修复绑定**（不允许带 bug 毕业）：毕业被推迟到修复时点，"等修的时候再毕业"≈永不毕业，单向机制形同虚设 → 拒绝；expected-fail 先行 + fixImmediate 旁路。
- **skip/fixme 承载未修复用例**：skipped 测试无人看管逐渐腐烂，且是最顺手的降级后门 → 拒绝。
- **quarantined 隔离态**：防降级的头号后门，任何测试都可在"先隔离"名义下静默降级 → 拒绝；偶发失败视为新缺陷（修或显式退役）。
- **内容哈希防篡改**：能抓内容级弱化，但绊倒合法重构/格式化，每次重构须跑 `--repair` → v1 不做，记入地图迷雾。
- **GitHub issue 号 / ULID 作缺陷 ID**：发现时尚无 issue；ULID 人读不友好 → `DEF-NNNN` 递增 + 撞号机械重排。
- **tag 区分双轨 / 毕业时编辑 CI YAML 挂载用例**：tag 纪律可漏、YAML 写入点易冲突 → 目录约定 + 独立配置自动生效，毕业只验证收集（`--list`），不改 CI。

## 后果

- GLOSSARY.md 建立首批术语（探索轨道/复现轨道/毕业/缺陷报告/复现门禁/退役）。
- #13 原型按此实现全流程演示（含防降级校验与反向拒绝）；退出码枚举表、JSON 输出字段在原型定型。
- 复现用例内容级弱化是 v1 接受的残余风险，靠 PR review 与探索轨道再发现兜底；真实摩擦出现再启用 codeHash。
- 探索调度常态化、缺陷接入 triage 五标签体系仍留地图迷雾，待毕业机制落地后另开票。
