## 背景

Spec-e2e §5 要求复现门禁**由 report 命令实测**（起隔离栈跑 `replayCommand` N 次，回填
gate 证据），**非自查申报**；按**被测路径**分类（纯函数/无外部状态 1 次；依赖外部状态/
并发在独立键空间 ≥3 次），且每次须「从明确前置状态开始、在同一断言处因同一原因失败」，
并发缺陷须保留触发时序。**次数是检查预算不是证明**。

原型（`prototype/e2e-dualtrack`）的 `report` 是**自查申报形态**：宿主跑 N 次收集退出码，
把 `--outcomes 0,0,…` 传给 CLI，CLI 只校验「全 0 且次数够」就回填 `gate{attempts,
keySpaces,allFailed}`。它按**引擎**分类（deterministic/nondeterministic），不比对失败
签名，也不记录每轮前置状态。NOTES-e2e §1.5 已记该口径过时。本票在 #106 事实源/决策
引擎、#107 属性发现产物、#108 签名原语与 per-run 重放编排之上，把门禁做成**机器判定
的实测事务**，并产出 dev 首条入库缺陷记录作为下游（#110 毕业 / #112 CI 判定 / #116
校验器 / #117 演练）的稳定夹具。

## 决策

1. **门禁按被测路径分类，不按引擎**：`reproducibility.kind`（#106 已定型 `pure` |
   `external-state`）决定预算——`pure` 1 轮、`external-state` ≥3 轮。`--attempts` 只可
   **上调**，低于路径下限 → exit 2（检查预算不得下调）。同一规则缺口在纯契约路径与
   API+DB 路径上是**两个不同 kind**，预算不同（本票以临时夹具实证 pure 1 轮）。
2. **三段式：plan（只读取号）→ 宿主实测 N 轮 → register（判定 + 原子落账）**。
   决策全在容器内纯引擎（`apps/e2e/src/cli.ts` 的 `report plan|register|
   finding-from-results`），落盘全在宿主（op 行协议原子应用）。**门禁不过 → END error 8
   → 零 op → 工作区零改动**；不存在「先登记再回填」的中间态。
3. **引擎桥：树 tar 与发现载荷同一 stdin 通道**。report 既需事实源树（取号、编号/脚本位
   占用核对、派生缓存重建）又需发现载荷，#108 的无状态签名桥（只送载荷）不足以承载。
   定型：载荷作为 tar 成员 `.report-payload.json` 与 `defects/replay/tests/.registry.json`
   同批只读进容器，解包到 `/tmp/in` 后**以该成员为 stdin** exec 引擎（`--root /tmp/in`）。
   无 bind 架构的读取通道语义不变，引擎侧无需新增旗标（`readStdin` 接缝照旧可注入单测）。
4. **脚本在登记前实测，注入执行器的入库路径**：载荷携带 `replayScript` **源码**（不是
   路径）。plan 输出脚本字节（base64 数据线），宿主解码到临时暂存目录，每轮经 stdin tar
   注入 `/workspace/apps/e2e/replay/<ID>.mjs`，再行使同一条 `replayCommand`——「实测的
   就是登记后那条命令」。过门禁后脚本与记录**同一事务**入库。
   **`gate.scriptSha256` 绑定实测字节与登记字节**，不符 → exit 8（门禁证的必须是入库
   那份复现面）。
5. **每轮独立键空间 + 明确前置状态（实测建立，非声明）**：复用 #70/#108 per-run 机制，
   每轮一个 run id（`<base>-a<k>`，`track=report`）→ 独立库/bucket/队列；前置状态 =
   `DROP DATABASE … WITH (FORCE)` + `CREATE` → `migrate deploy` → 空桶 → 空队列，无种子。
   载荷 `precondition` 是**声明**，`gate.rounds[].precondition` 是宿主**实测建立**的状态，
   二者互为证据。键空间独立性是**机器核对项**：run id / 库 / 桶 / 队列各维度均须互异，
   否则 exit 8（同库重复重放撞 `name` 唯一约束会伪装成「未复现」）。轮次间串行。
6. **逐轮签名比对用 #108 同一原语**（`compareSignatureSet`，本地与 CI 同一判定器）：
   基线 = 首轮签名，逐轮比对结果（`matched/reason/differences`）回填 `gate.rounds[]`。
   **单轮无从跨轮比对 → `signatureMatched=null`，不是 true**（沿用 #108 口径，不自证同一）。
7. **保守档永不过门禁**：`errorClass=unknown`（证据不足以分类）与 `infrastructure`
   （环境故障不是缺陷复现）一律 exit 8 零登记；无哨兵行 → `signature=null` → 同样 exit 8。
   `locator` 可承载证据但置 `gate.needsHumanJudgment=true` 留痕（Spec §7「需人判断是
   UI 改版还是缺陷」）；其红/绿判定矩阵归 #112 CI 判定器，不在门禁里发明规则。
8. **退出码分档：轮次内基础设施错误归 8，环境级未就绪归 3**。门禁轮次**跑起来了**但
   脚本自述基础设施错误（exit 2 或 `errorClass=infrastructure`）→ 那一轮没有缺陷复现
   证据 → **门禁不过 8**；共享基础设施未起/镜像未绑定/健康等待失败 → 环境未就绪 3/5。
   二者不可混淆：前者是「这个发现没被证明可复现」，后者是「还没能开始证明」。
9. **gate 证据 schema 增量全部 optional（向后兼容）**：`GateSchema` 增 `rounds[]`
   （`attempt/runId/keySpace/precondition/scriptExitCode/verdict/signature/comparison`）、
   `precondition`、`baselineSignature`、`compareReason`、`measuredAt`、`scriptSha256`、
   `needsHumanJudgment`；`signatureMatched` 由 `boolean.optional` 放宽为
   `boolean.nullable.optional`（承载单轮 null）。#106 既有记录（含 `attempts=0` 占位）
   无需迁移即可继续解析。另增 `ConcurrencySchema` 与 `reproducibility.concurrency`、
   `CounterexampleRequestSchema.bodyBase64`（二进制反例留位），均 optional。
10. **并发缺陷保留触发顺序与时序是约定 + 声明位**：`concurrency.triggerOrder`（逐步操作
    顺序）/`timing`（可复验时序描述）/`preservedBy`（脚本如何保留）。声明在场 ⇒ `kind`
    必为 `external-state`（并发必然依赖外部状态），否则 exit 2。脚本不得把有序触发改写为
    无序并发或省略等待；时序参数经 env 注入时须把实际取值打进签名语义标记，使「时序条件
    变了」表现为签名不符而非静默通过。本票不发明并发缺陷（无现成素材），只定型约定与
    声明位，供 #114 charter 会话消费。
11. **登记产物完整 + 运行登记册关联**：`defects/<ID>.json`（`status=reported`）+
    `replay/<ID>.mjs` + `.registry.json`（派生缓存同事务重建）经 op 协议原子应用；
    **登记成功后**才把 `defectId` + `gateRole=report-gate-round` 写回各轮
    `.devenv-state/e2e-runs/<run-id>.json`（门禁不过零登记，亦不留缺陷关联）。
    `evidence` 逐轮指向 `.artifacts/e2e/<run-id>/replay.json` 与 `logs/api.log`（只存 URI）。
    `issue` 字段**留空**作 tracker 回链位（写入归 #114）。**不自动 commit**。
12. **编号与并发**：plan 阶段只读取号（本地 max+1，`--remote` 经 `devenv gh` 叠读远端
    best-effort）；register 阶段在 **per-worktree 生命周期写锁**单一临界区内重核编号/
    脚本位占用，被占用 → exit 8 要求重跑（跨 worktree 撞号由 #116 renumber 收敛）。
    **锁序：stack 共享租约（门禁轮次全程）→ lifecycle 排他写锁（登记）**；无反向持有者
    （`registry rebuild` 只取 lifecycle 锁不取栈锁），故无环。
13. **首条入库记录 DEF-0001 = 纯空白点名缺陷**（原型 DEF-0002 lineage，dev 未收紧）：
    发现由 #107 缺口探针 `GAP-PT-NAME-01`（`E2E_CHARTER_GAPS=1`）产出结构化反例，
    `engine=fast-check`（机械引擎 → #110 可直通转写），`kind=external-state`，3 轮独立
    键空间实测。dev 编号从新开始（无既有入库记录）故为 DEF-0001；原型编号 lineage 记在
    `summary`/`charter`。它是下游 #110/#112/#116/#117 的稳定夹具。

## 考虑过的选项

- **沿用原型「宿主收集 outcomes → CLI 校验全 0」**：否决。那是自查申报的变体——CLI 只看
  退出码，不比对签名、不记前置状态、不核键空间独立性，无法区分「同一断言同一原因」与
  「三次不同的偶发失败」。本票把逐轮签名与键空间坐标都变成**机器核对项**。
- **先登记（attempts=0 占位）再实测回填**：否决。会产生「已入库但门禁未过」的中间态，
  与「门禁不过不登记」矛盾，且失败路径要回滚已入库记录。三段式把落账放在判定之后，
  失败即零 op，无需回滚。
- **载荷经命令行参数（base64）传入，复用 #106 树 tar 桥**：否决。脚本源码可达数 KB，
  命令行长度与转义都是脆弱面；且 `--root` 与载荷两条通道混用会让协议更难核。tar 成员
  方案保持「一切经 stdin 只读进容器」的既有架构。
- **pure 路径不起栈（省资源）**：否决（本票）。统一走 per-run 隔离栈使前置状态对两类
  路径都**显式且同构**，避免「pure 路径的前置状态是什么」变成隐式约定；代价是 pure
  夹具也起一次栈（可接受，1 轮）。
- **门禁里把 `locator` 一律判不过**：否决。Spec §7 的「红 + 待判断」是 CI 判定器
  （#112）的判定矩阵；门禁问的是「是否稳定可复现」，稳定匹配的 locator 失败确实是稳定
  复现。本票只置 `needsHumanJudgment` 留痕，不越票发明规则。

## 后果

- **正面**：门禁成为可机器复核的实测事务——每轮的 run id / 键空间坐标 / 前置状态 /
  签名 / 比对结果全部入库，第三方可据 `.artifacts/e2e/<run-id>/` 与运行登记册复核。
  保守档（unknown/infrastructure）与「无签名」一律零登记，偶发误报与环境故障进不了账本。
  脚本字节哈希绑定使「门禁证的」与「入库的」是同一份复现面。
- **正面**：gate schema 增量全 optional，#106 记录与 #108 冒烟夹具无需迁移；
  `replay.json` 与 #108 同形，下游证据消费面一致。
- **代价**：report 是长命令（external-state 至少 3 轮起栈/拆栈），实测成本显著高于
  原型单轮；这是「次数是检查预算」的必然代价，轮次间串行以免键空间互相污染。
- **代价**：pure 路径也起隔离栈（统一前置状态口径的代价）。
- **盲区（如实记录）**：① 签名比对只核「同一断言同一原因」，**不核断言是否真的行使了
  被测路径**——脚本若空转并打标记，门禁会过；该盲区由 #110 毕业真跑 + #112 CI 判定
  （核对断言真实执行）与 #117 演练兜底。② `concurrency` 是声明位 + 约定，命令**不机器
  校验脚本是否真的保留了时序**（无法从静态源码判定）；靠 PR review 与 #114 charter
  会话纪律。③ 远端编号叠读 best-effort，远端不可用时只用本地 max+1，撞号由合入时
  renumber 收敛。④ 产物导出失败但门禁已过时仍登记（记录已成立），只 WARN 提示证据 URI
  可能不可解析。
- **后续**：#110 消费 DEF-0001 做毕业转写（机械引擎直通）；#112 消费其签名做 CI 预期
  失败判定；#113 回收窗口须豁免门禁轮次产物直到记录入库（本票产物在 gitignored 证据区，
  记录内只存 URI）；#114 写 `issue` 回链并认领 charter；#116 把「graduated 记录必须含
  签名」「编号唯一无洞」接进 verify 聚合。
