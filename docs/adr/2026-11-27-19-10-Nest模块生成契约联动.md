- 相关：[OpenAPI 契约派生](https://github.com/bbhl79/natural-enforcement-prj/issues/66)、[新增包生成闭环](2026-11-27-17-45-新增包生成闭环.md)

## 背景

原型 #12 的 `gen nest-module` 只生成一个返回空列表的 controller：路由、请求/
响应 schema、校验、OpenAPI 与测试都需要事后手工补齐，是「假完整」骨架。原型
NOTES 已把它记为 SPEC 待议项；Spec-工程基座 §5 的决议是「契约联动仅 HTTP
kind，internal kind 不强制契约」。本 ADR 记录该决议的落地接口。

## 决策

1. **命令面**：`devenv gen nest-module <name> --http|--internal --spec <仓库相对
   路径>`。variant 必须显式二选一；`--spec` 为必要业务信息，必须位于仓库内且
   未被 gitignore（随固定快照经 stdin tar 进入生成器容器）。缺失、空
   `fields`、非法 JSON 或路径不安全 → exit 2，生成前停止，无部分写入。
2. **spec 是业务信息的唯一载体**：`{ description?, basePath?, fields }`；
   `fields` 非空，字段支持 `string | integer | number | boolean` 与
   `minLength/maxLength/minimum/maximum/optional`。生成器拒绝未知键、保留字段
   （`id`/`createdAt`）与越界约束，避免拼出会破坏响应 DTO 的模板。
3. **HTTP kind 生成完整闭环**：
   - `packages/contracts/src/<name>.ts`：`<UPPER>_ROUTES`（base/create/list）、
     `Create<Pascal>Schema`（请求）、`Create<Pascal>ResultSchema`（201）、
     `<Pascal>DtoSchema` / `<Pascal>ListResultSchema`（响应）与
     `<UPPER>_ENDPOINTS` 清单；
   - `apps/api/src/<name>/`：module、controller、service 与集成测试；
     controller 用 `@Body({ schema, pipes: [ZodValidationPipe] })` 做请求校验、
     `ApiContractResponse` 同时绑定运行时响应校验（StandardSchemaSerializer）
     与 OpenAPI 响应 schema；
   - 契约文件经 `api-registry.ts` 的 `// @gen:endpoint-import` /
     `// @gen:endpoint-spread` 整行锚点进入 `API_CONTRACT_ENDPOINTS`，从而被
     #66 完整性检查覆盖（正向端点/schema 一致 + 反向未登记端点检出）；
   - 集成测试真实启动应用，断言 201/400/list 与 OpenAPI 完整性，开箱即跑。
4. **internal kind 不生成 HTTP 契约**：只生成 module/service/单测并登记
   `app.module.ts`；不生成 controller、契约文件或 OpenAPI 清单条目。
5. **整行锚点自动注册**：`app.module.ts` 的 `// @gen:module-import` 与
   `// @gen:module-entry`；`api-registry.ts` 的上述两个标记。生成器要求每个
   标记恰好一处命中，追加内容以整行为单位声明在 manifest；宿主核对「旧/新文件
   中该整行出现次数增加声明次数」且「去掉新增行后与快照锚点逐字节一致」，
   非整行修改一律拒绝。目标目录/契约文件已存在或锚点已注入同名行 → exit 4。
6. **不触发 lockgen**：nest-module 不新增 workspace 包，不改变
   `workspace.Dockerfile` 与 lockfile；仍执行静态供应链门禁。因此其事务回滚
   只需删除新文件（含新建空目录）并恢复补丁备份。
7. **示例实现边界**：生成的 service 是可直接调用/测试的内存存储实现；接入真实
   持久化时替换 `create`/`list`。契约、请求/响应校验、OpenAPI 与测试是生成物
   的稳定部分，不要求事后补齐。

## 后果与边界

- spec 是声明式字段模型，暂不支持嵌套对象/数组/枚举；出现这类需求时先在
  spec 格式上扩展（并补生成器与离线测试），不在生成后手工补契约。
- 生成契约直接进入 `@ne/contracts` 的同一注册表；多个模块的生成互不重叠，
  但同一名称的模块/契约文件不可重复生成。
- 宿主对补丁的校验是「只允许整行追加」的结构性检查，不声称抵御恶意生成器；
  生成器仍被视为当前工作树的可信代码（来源哈希可核）。
- HTTP 生成物的 OpenAPI 完整性、lint/typecheck/test 与 internal 生成物的
  lint/typecheck/test 需在真实引擎上留证；本机为 Windows WSL2，证据按票归档。
