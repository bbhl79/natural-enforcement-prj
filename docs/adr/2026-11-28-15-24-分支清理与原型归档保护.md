## 背景

Spec §7 要求：远端 PR 分支合入后自动删；本地分支/worktree 清理前检查未保存工作
（未推送提交 + 未提交文件），**清理命令不得强制删除，发现未保存工作拒绝并列出
原因**；squash 合入判定 = PR 状态（远端合并发生）**且本地无未推送内容**（本地可能
事后增提交）；`prototype/*` 留档豁免；`archive/*` 标签保护（禁更新/删除）+ 验收
记录提交哈希为准，保证源码可追溯，不承诺环境可重建。#73 已交付 dev 两层规则集
与漂移核对入口；#74 复用其保存配置即代码 + CI 常驻核对 + 受控验收方法论。

## 决策

1. **窄用途命令 `branch-cleanup <branch> [--apply]`，不引入通用 worktree 管理器**：
   只做「PR 合入后清理本地分支与其 worktree」。默认 dry-run（宁多留勿误删，与
   镜像回收 §10 同口径），`--apply` 才删除。无创建/切换/通用管理面（AC3）。
2. **双重判断闸门，squash 以 PR head.sha 为基准**：squash 合入后原分支提交非 dev
   祖先，`git merge-base --is-ancestor` 与 `git branch -d` 都无法识别——故判定取
   远端 PR 的 `head.sha` 为合入基准，`git rev-list <head>..<branch>` 非空即「合入后
   本地新增提交/未推送内容」拒绝。三类反例（未提交文件 / 未推送提交 / 合入后新增）
   分别收集原因并列出（AC2）。PR 查询失败或合入 head 不在本地对象库 → fail closed
   （exit 3），不删除。
3. **无用户可见强制路径，原子 compare-and-delete + 活跃运行保护**：「不得强制删除」
   解释为命令面不暴露跳过闸门的旗标（`--force` 即 exit 2），而非禁止内部删除已验证
   安全的分支。git `branch -d` 不识别 squash，故闸门通过后用 `git worktree remove` +
   `git update-ref -d refs/heads/<branch> <判定基准tip>`——`update-ref -d` 带旧值即
   **原子 compare-and-delete**（ref 在判定后变动即删除失败），删除前再核 tip，关闭
   判定→删除 TOCTOU。清理是写者：目标 worktree 持活跃 `stack-<wt>` 锁/租约即拒
   （exit 6，绝不强拆）——gitignored `.devenv-state` 对 `git status` 不可见，故按
   锁/租约持有者存活独立判定（Spec §4 栈使用租约语义）。`prototype/*` 豁免、
   `dev`/`main`/当前检出分支恒拒（exit 4）。
4. **archive 标签规则集 = update + deletion（无绕过），durable + CI 常驻**：
   `target: tag`、`include: refs/tags/archive/*`、`{type: update}`（Restrict updates，
   禁一切推送更新含移动）+ `{type: deletion}`（Restrict deletions）。**不加 creation**
   ——允许创建新归档标签。无 bypass_actors（App 与日常身份均不可更新/删除；管理员
   仍可改规则集本身）。进 `BP_DURABLE_RULESETS`，`devenv branch-protection` 核对，
   削弱归档保护会使 CI 必需检查变红（自锁闭环，与 dev 两层同构）。额外 tag 规则集
   覆盖 archive/* 命名空间判漂移。
5. **自动删除设置可见性拆分（与 bypass_actors 同口径）**：`delete_branch_on_merge`
   需管理员开启（App 无 Administration）；实测匿名/`contents:read` 令牌的
   `GET /repos` 不返回该字段，带 push 权限令牌才返回。核对拆三面：公开面缺失记
   NOTE 跳过（不死锁匿名本地核对，保留「零凭据随手可跑」）；管理员强校验缺失
   fail closed；存在则严格核对 true/false。**CI（contents:read）同样走公开面
   NOTE 跳过**——自动删除的生效闭环不依赖 CI，而是 harness `verify-config`
   （App 身份）+ 指挥者管理员核对（见取舍节评审整改条）。
6. **受控验收方法论（项 11「一次 + 一平台」）**：清理逻辑反例由离线测试以真实 git
   沙箱 + mock GitHub 覆盖（一平台，代码逻辑）；真实 GitHub 配置面（自动删除实际
   生效、archive 标签实际禁更新/删除、真实合入 PR 清理正例）由 harness 覆盖（一次），
   指挥者 UI 操作与 agent 阶段交错。**archive 反例前置断言保护 active 且 App 无
   绕过权**，否则不尝试（避免无保护时误改真实归档标签）；被拒即零写入，前后核对
   标签提交哈希不动。验收记录写入提交哈希，以哈希为最终定位依据。

## 取舍与已知边界

- **`update` 规则的 `update_allows_fetch_and_merge` 参数**：该参数是分支语义（上游
  拉取合并），标签规则集省略。应用后 `verify-config` 逐字段核对实时形态；若 GitHub
  对标签 update 规则物化出该参数，按两步锁齐流程对齐保存配置（一行 JSON + UI 同步）。
- **`non_fast_forward` 未纳入 archive 规则集**：`update`（Restrict updates）已禁止
  一切推送更新（含 force），语义上覆盖并强于 `non_fast_forward`（仅禁 force）；
  单用 update + deletion 即满足「禁更新/删除」，避免冗余规则与参数歧义。
- **匿名本地核对的自动删除面**：匿名读不到 `delete_branch_on_merge`，本地匿名
  `branch-protection` 对该设置记 NOTE 跳过（不谎报已核对）；其生效由 CI（github.token）
  与指挥者管理员核对保证。这与 #73 bypass_actors 公开面拆分同构。
- **归档不承诺环境可重建**：archive 标签 + 提交哈希保证**源码**可追溯；旧镜像/外部
  依赖永远可下载、旧环境未来可重跑**不在承诺范围**（spec §7 同款声明）。
- **探针 PR 靶为测试分支**：合入正例不向 dev 写入无效变更（与 #73 受控验收同口径）；
  自动删除对头分支生效与靶分支无关。archive 反例用真实已有归档标签作靶（零写入），
  不创建新永久探针标签（archive/* 受保护不可删，避免测试污染）。
- **清理不持栈锁，但拒绝活跃运行**：branch-cleanup 不触引擎/运行栈，纯本地 git +
  匿名 GitHub 只读判定，不取得栈锁；但删除是写操作——目标 worktree 持活跃锁/租约
  即拒（exit 6），删除用原子 compare-and-delete 兜底并发。已登记 COMMANDS.md 并发表。
- **CI 不授予写权限读自动删除设置（评审整改，2026-11-29）**：`delete_branch_on_merge`
  仅对具 push 权限的令牌可见（匿名/contents:read 的 GET /repos 不返回，实测）。曾考虑
  给 quality-gate job 授 `contents: write` 读取该字段，**经评审否决**：规则集仅保护
  `refs/heads/dev`，`pull_request` 触发的 job 执行 PR 代码与依赖全程持写权限，可击穿
  `prototype/*` 留档分支（本票自身保护目标）/篡改 main 与开放 PR 分支——不为读单个
  管理员开关把整个质量门提权。故 CI 保持 `contents: read`，自动删除设置走公开面
  NOTE 跳过；其生效闭环 = harness `verify-config`（App 身份带 push 权限）+ 指挥者
  管理员核对（`--require-bypass-actors` 或 UI 复核）。dev/archive 规则集本身的漂移
  核对不受影响（规则集端点匿名/低权可读，CI 自锁闭环依然成立）。
- **额外规则集检测的 name-trust 边界（与 #73 同类漏检边界）**：durable 规则集按名
  豁免「额外覆盖面」判定（使只核对 dev 两层的调用方不误报 archive 层）。一个 live
  规则集若**冒用** durable 名（如名为 protect-archive-tags 却 target=branch 覆盖 dev），
  在只请求子集的调用方下会逃过覆盖面判定；但 CI 常驻核对请求**全部** durable 名，
  冒用者会被逐字段比对（target/内容不符）判漂移。即子集调用方的漏检由 CI 全集兜底，
  与 #73「比 dev 更窄的 glob 精确覆盖不在机械检测范围」同属已声明的可解释性取舍。
- **archive 创建允许靠规则集形状（无 creation 规则）**：`update`+`deletion` 不含
  `creation`，故创建新 archive/* 标签允许。创建-允许是规则集形状属性；受控验收
  由指挥者创建归档标签实证（negatives 只打更新/删除反例，不创建永久探针标签以免
  测试污染——archive/* 受保护不可删）。
