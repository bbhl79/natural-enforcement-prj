# per-worktree 运行资源隔离

- 状态：accepted
- 日期：2026-11-25
- 决策记录：[Spec-工程基座](https://github.com/bbhl79/natural-enforcement-prj/issues/23) 硬不变量 4；实施票 [#59](https://github.com/bbhl79/natural-enforcement-prj/issues/59)；前置机制 #58（不可变绑定）、#56（最小栈）

## 决策

compose 项目名/本地镜像 tag 按 **worktree 身份**派生：身份 = git 目录路径
（`git rev-parse --absolute-git-dir`）的 sha256 前 8 hex。派生 `natural-enforcement-<8hex>`
compose 项目（容器/卷/网络随之 per-worktree 独立，compose.yaml 不再写死 `name:`）与
`natural-enforcement/{tools,workspace}:wt-<8hex>` 本地 tag。数据库凭据每 worktree
随机生成（`openssl rand -hex 16` → 32 hex），持久化 `.devenv-state/db-credentials.env`
（0600，gitignored），db `POSTGRES_PASSWORD` 与 api/tools `DATABASE_URL` 同源注入。
锁分派：stack/migrate 锁加 `<8hex>` 后缀 per-worktree；**lockgen 机器级**（其
`ne-lockgen:tmp` 标签与同名遗留容器清理是唯一跨 worktree 共享的可变资源）；
migrate:create 容器名带后缀。镜像内容仍按不可变产物共享：同快照 + 同 tools 输入
→ 同 image ID（存储层内容寻址去重），运行正确性由 #58 的不可变 image ID 绑定保证，
per-worktree tag 只解决归属可辨，不替代绑定。**新鲜度命中仍须登记 tag**
（#84 评审修复）：`ensure_tools_image`/`ensure_fresh_workspace` 在
tools.fresh / workspace.fresh 命中返回前执行 `docker tag <不可变 ID> <wt tag>`——
采纳既有镜像与全新构建在 tag 登记上不分叉，否则 #75 回收核对与人工排查失去归属
依据；登记失败显式报错（exit 4），不静默跳过。

## 背景

- 硬不变量 4 要求"每 worktree 一套完整隔离环境"：多 agent 在各自 worktree 同时
  开发时，完整运行栈、数据和访问地址互不受他人构建、迁移或拆栈影响。
- #59 前 compose 项目名写死 `natural-enforcement`：两个 worktree 的 `devenv up`
  争夺同一组容器/卷/网络（后启动者静默替换先启动者的运行代码，SPEC 原型实测隐患），
  stack/migrate 锁机器级（B 的拆栈被 A 的锁阻塞或更糟）。
- 机器上已有 #59 前共享项目 `natural-enforcement` 的运行容器与卷（遗留资源）。

## 考虑过的选项

- **身份取工作树根路径哈希**：拒绝。worktree 目录改名/移动即换项目名，旧运行资源
  被"遗弃"而非复用；git 目录路径对 worktree 改名稳定。非 git 上下文回退路径哈希
  （离线沙箱，source 期不 die）。
- **凭据沿用固定值（各 worktree 同口令）**：拒绝（弱化"凭据独立"验收项，且未来
  对象存储接入时同样要求 per-worktree）；**每次 up 重生成**：拒绝（数据卷按初始
  口令初始化，换装即连接失败；口令是 worktree 身份不是数据，须随状态稳定）。
- **迁移兼容：检测遗留卷 → 沿用旧固定口令**：拒绝。per-worktree 项目名使每个
  worktree 获得全新卷（postgres 全新初始化，随机口令天然一致），不存在"旧卷+
  新口令"冲突；旧共享卷成为无归属遗留资源，回收归 #75。
- **镜像 tag 保持共享 `tools:local`/`workspace:local`**：拒绝（SPEC §3 明令
  "镜像 tag per-worktree"；共享 tag 使 `docker image ls` 归属不可辨，B 覆盖 tag
  虽不影响 A 的运行绑定（#58），但误导人工排查与 #75 回收）。
- **新鲜度命中跳过 tag 登记**：拒绝（#84 评审发现的真实缺口：取证时 A 采纳
  既有 tools 镜像后无 `wt-<suffix>` tag）。tag 是归属职责，不随"构建还是采纳"
  分叉；命中路径补 `docker tag`，失败显式退出。
- **down 顺手清理遗留共享项目**：拒绝。per-worktree down 触碰共享项目会把
  "隔离"变成"跨 worktree 拆栈"；遗留资源由 doctor warn 提示、#75 保守回收
  （宁多留勿误删）。

## 后果

- `devenv` 命令在任意 worktree 内即得独立栈；A 保持运行时 B 的
  build→up→migrate→down 不影响 A 的容器/卷/网络/凭据（验收反例见
  docs/evidence/59-worktree-isolation/）。
- 每个 worktree 独立 pgdata/turbo-cache 卷：磁盘占用随 worktree 数线性增长
  （资源占用实测归容量票）；turbo-cache 隔离消除了跨 worktree 缓存竞争。
- `.devenv-state/` 新增 `db-credentials.env`（0600）；凭据损坏（非 32 hex）→
  exit 3 并内嵌修复命令（删文件 + down --volumes 重建）。
- 离线测试注入点 `DEVENV_WORKTREE_ID`：仅测试用，生产身份始终取 git 目录。
- 遗留共享项目 `natural-enforcement` 的容器/卷不被任何 worktree 管理：
  doctor warn（不失败），回收归 #75。
- **已声明残余**：① web 宿主端口 `--port` 默认 5173 为各 worktree 共享值——
  B 在 A 已发布时绑定失败发生在 B 侧（响亮报错），A 的访问地址不受影响；
  并发 web 入口（派生/动态端口）归 #62。② 对象存储凭据当前为空集（#56 最小栈
  无 rustfs）；服务回归时必须复刻 `db_credentials_ensure` 模式（每 worktree 生成 +
  `.devenv-state` 持久化 + compose 同源注入），归该服务实施票并与 #75 核对衔接。
