## 背景

原型 #12 的 `gen page` 仅产出静态卡片占位页，不消费 `@ne/contracts`，也不带表单与测试；既有前端页面 `NearbyPanel` 与 `CreatePointForm` 均使用无 `name` 的 Ant Design `<Form>`，在同一页面同时渲染时已出现 `id="lat"` / `id="lng"` 重复；此外，根级 ESLint 10 flat config 只启用了 `eslint-plugin-react-hooks`，缺少 `eslint-plugin-react` 正确性规则面，且 `apps/web/vite.config.ts` 手工硬编码代理路由，新生成的后端 HTTP 路由无法开箱经 `devenv web` 转发。

## 决策

1. **命令面与契约强绑定**：
   `devenv gen page <name> --spec <仓库相对路径> [--contract <契约名>]`。
   - `--spec` 复用 #67 的声明式字段模型（扩展可选顶层 `title` 与字段级 `label`）；`label` 在**规范化空白之后**判重（换行/制表/NBSP/U+2028/U+2029 折叠为单个空格），避免「相同 标签」与「相同\n标签」生成同可见标签；
   - `--contract` 默认与 `<name>` 同名，必须指向 `@ne/contracts` 中已导出的 create/list HTTP 契约（如 `#67 gen nest-module --http` 生成物），且端点必须已登记到 `API_CONTRACT_ENDPOINTS`（`api-registry.ts` 的整行 `import { <UPPER>_ENDPOINTS } from './<contract>.js'` 与 `...<UPPER>_ENDPOINTS,`）；仅从 `index.ts` 再导出不算——vite preview 代理由端点清单派生，未登记会生成「能过类型检查但真实 API 无代理路由」的页面；
   - 缺失 spec、空 `fields`、缺失契约、契约不含 create/list 导出、未登记端点、`Create<Pascal>Schema` 字段集合/zod 表达式与 spec 不符或 label 规范化后重名 → exit 2，生成前停止（零写入）；同名页面目录或 `App.tsx` 已注入同名 key/import → exit 4。
2. **统一响应校验与无补丁端点扩展**：
   - 生成物 `apps/web/src/pages/<name>/<name>.api.ts` 通过 `neApi.enhanceEndpoints({ addTagTypes: [CONTRACT_TAG] }).injectEndpoints(...)` 注入 `list<Pascal>Page` 与 `create<Pascal>Page`，路由常量与推断类型全部来自 `@ne/contracts`，响应全部经 `apps/web/src/lib/validate.ts` 的 `validated(...)` 统一校验封装；
   - `apps/web/src/api.ts` 采用运行时解析同源基准的 `dynamicBaseQuery`（浏览器走 `window.location.origin` 同源经 Vite preview proxy；Node 26 / jsdom 下避免 `new Request('/...')` 解析报错；容器内真实栈测试经 `setApiBaseUrlOverride` 直连 `http://web:4173`）；
   - `apps/web/vite.config.ts` 的 `apiProxy` 直接从 `@ne/contracts` 的 `API_CONTRACT_ENDPOINTS` 派生，并设 `preview.allowedHosts: ['web', 'localhost']`（Vite 8 默认拒绝非 `localhost` Host 头导致容器内网 `http://web:4173` 返回 403），保证已登记的 HTTP 路由开箱可调、零手工同步。
3. **表单实例唯一与多 React 根前缀**：
   - 新增 `apps/web/src/lib/root.tsx`（`createWebRoot`），统一为 React 19 `createRoot` 传入 `identifierPrefix`（主入口默认 `ne-web-`；省略时自动分配递增前缀 `ne-root-N-`），保证同一文档挂载多个 React 根时 `useId()` 输出携带不同根级前缀；
   - 生成的 `<Pascal>Form.tsx` 以及既有 `CreatePointForm.tsx` / `NearbyPanel.tsx` 均使用 `const formId = useId()` 传给 Ant Design `<Form name={formId}>`，使所有表单及控件 DOM `id` 与 `<label for>` 具备实例级唯一性且跨根隔离；
   - 验收必须实际渲染两个相同 Form 与两个独立 React 根并断言真实 DOM `id` 唯一、根前缀生效、`label.control === target`（而非静态检查源码）。
4. **整行锚点自动注册、不触发 lockgen**：
   - `apps/web/src/App.tsx` 采用 `<Tabs>` 布局并提供两处整行锚点：`// @gen:page-import` 与 `// @gen:page-item`（支持 `?tab=<key>` 初始定位到指定注册页）；
   - 生成物全部位于 `apps/web/src/pages/<name>/`（4 个文件：`*.api.ts`、`*Form.tsx`、`*Page.tsx`、`*Page.spec.tsx`），不新增 workspace 包/依赖，不触发 lockgen，落盘后仍执行静态供应链门禁。
5. **`eslint-plugin-react` 最小正确性规则面（ESLint 10 flat config）**：
   - 在 `pnpm-workspace.yaml` catalog 精确 pin `eslint-plugin-react: "7.37.5"`（零新增 `allowBuilds`、零包内 agent skills）；
   - 根级 `eslint.config.js` 在 `apps/web/**/*.{ts,tsx}` 块显式挂载 13 条正确性 error 规则（`jsx-key`、`jsx-no-comment-textnodes`、`jsx-no-duplicate-props`、`jsx-no-target-blank`、`no-children-prop`、`no-danger-with-children`、`no-direct-mutation-state`、`no-find-dom-node`、`no-is-mounted`、`no-render-return-value`、`no-string-refs`、`no-unstable-nested-components`、`void-dom-elements-no-children`），不启用与 TS 6 strict 重复或纯风格规则；
   - 显式声明 `settings: { react: { version: '19.3' } }`（对齐 catalog React 19.3.1），避开 `version: 'detect'` 在 ESLint 10 下的兼容坑，无需额外引入 `@eslint/compat`；13 条规则均经真实 ESLint 10 反例探针证实命中 `severity: 2`。
6. **UI 校验规则与 zod 语义对齐**：
   - 字符串未声明 `minLength`（或 `minLength: 0`，含 `maxLength: 0` 的空串契约）时，`z.string()` 接受空串，生成物**不得**加 Ant Design `required`；仅当必填且 `minLength > 0` 才加 `required`。未触碰的必填字符串序列化为 `''` 而非 `undefined`，避免 zod 拒绝 `undefined`；
   - 可选字符串的长度规则对空值放行（空值由 payload 构建器省略），防止「zod 允许省略、UI 却阻止提交」的语义漂移；
   - 真实引擎冒烟夹具包含 `maxLength: 0` 必填空串字段，并在生成物源码与提交回显两处断言其可提交。

## 后果与边界

- `gen page` 与 `#67 gen nest-module --http` 组成垂直切片生成链路：先生成后端模块与契约，再以同一 `--spec` 生成前端页面即可直接通过 `devenv verify` 与真实栈联调；暂不直接消费非 create/list 形态的手写端点（如 `enforcement-point` 的空间半径查询），遇该类契约会在生成前以 exit 2 明确拒绝。
- `apps/web/test/setup.ts` 补齐 `ResizeObserver` stub 与 `IS_REACT_ACT_ENVIRONMENT = true`，供 Ant Design 6 `<Tabs>` 与 React 19 多根 `createRoot + act(...)` 组件测试在 jsdom 下稳定运行。
- 真实引擎冒烟 `devenv/test/gen-page-smoke.sh` 将规则探针、页面生成、双 Form/多根测试、真实栈 `App → web proxy → api → 数据回显` 旅程、宿主独立 `curl` 核对及反例固化为可重复驱动，原始证据落 `.artifacts/68-gen-page/`。

## 评审整改（2026-11-28，PR #101）

1. **契约通过校验但 vite 无代理路由**：`verifyPageContract` / 宿主预检新增 `API_CONTRACT_ENDPOINTS` 登记要求（整行导入 + 展开）；仅从 `index.ts` 再导出的契约在生成前 exit 2。离线 T55/T56 与真实引擎冒烟「仅 index.ts 导出」反例覆盖。
2. **`maxLength: 0` 合法空串无法提交**：字符串规则仅在必填且 `minLength > 0` 时加 `required`；未触碰输入序列化为 `''`；可选长度规则对空值放行。冒烟夹具新增 `maxLength: 0` 字段，断言生成物无 `required`、`max: 0` 生效且提交回显成功。
3. **label 规范化前查重**：宿主与容器均在空白折叠（含换行/U+2028/U+2029）后判重；离线 T54 与真实引擎冒烟反例覆盖。
