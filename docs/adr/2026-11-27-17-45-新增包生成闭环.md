## 决策

1. **来源 = 本次调用当前工作树的完整 `devenv/gen/` 集合**，经 #58 固定输入快照
   采集；报告宿主路径、git 子树哈希（`treeHash`）与内容集哈希（`setHash`）。
   输入以 **stdin tar** 进入一次性容器（`--network none --read-only`），容器侧
   重算集哈希核对传输完整；镜像内不得有可静默 fallback 的烘焙副本
   （`.dockerignore` 排除 `devenv/gen`，容器入口断言 `/workspace/devenv/gen`
   不存在）。
2. **文件通道隔离**：生成器容器 stdout = 生成物 tar（含清单/哈希），由 devenv
   内部捕获到事务目录，**不经 devenv 的 stdout**；`--json` 结果流只有 JSONL。
3. **全有或全无**：宿主先列 tar 成员做路径/链接安全校验，再解包到仓库内
   `.devenv-state/gen-txn.*`；校验清单结构、文件集合精确相等、逐文件 sha256、
   补丁基准 sha256 与「只追加两行 COPY」后，以原子 `rename` 提交。lockgen
   成功前的失败回滚新包/Dockerfile/lockfile；lockgen 后的锁文件审查或供应链
   门禁失败保留现场供审查。
4. **联动**：`workspace.Dockerfile` 的 lockgen-base 与 deps 两靶各有一个
   `# @gen:pkg-copy` 标记，生成器要求恰好两处并各追加一行 manifest COPY；
   随后在机器级 `lockgen` 锁下重生成 lockfile。只接受「新增该包 importer」的
   预期 diff（去掉 importer 后新旧锁文件规范化逐字节一致），其它差异停止并
   要求审查。
5. **锁关系**：`gen package` 持 per-worktree `gen-<wt>` 排他锁；`build` 在
   stack 锁之后取得同一把（gen/build 互斥）；触发 lockgen 取机器级锁。其它
   只读消费命令不取 gen 锁——它们靠快照采集的 stat 括号/双读检出并发写入并
   明确拒绝，不与 gen 串行。
6. **下载证据**：`DEVENV_PNPM_EVIDENCE=1` 构建时 deps 层把 pnpm ndjson 事件
   摘要写入镜像；`gen evidence` 只读绑定镜像读取。只有事件流完整、`errors=0`
   且 `fetchedPackages=0` 才判「未变更依赖零包内容下载」；证据缺失/超时不默认
   通过。`devenv/test/gen-loop.sh` 负责同一基线 + 共享缓存的重复计时。

## 后果与边界

- 生成器随工作树演进即可生效，不需要重建镜像；生成器零第三方依赖，容器内只
  需 node + tar。
- 生成器被视为当前工作树的可信代码；tar 成员预校验用于防止损坏/意外的越界
  写入，不声称抵御恶意生成器。
- lockfile 比较是文本规范化（去空行、丢弃指定 importer），对 pnpm 的多文档
  锁文件成立；若 pnpm 格式变化导致误判，会以 exit 4 停止而不是静默接受。
- 本机为 macOS arm64，#64 AC5 要求的 **Windows** 5 轮中位数/最差值尚未取得；
  不得用 macOS 单轮结果冒充。Windows 实机在 WSL2 bash 内执行
  `devenv/test/gen-loop.sh --loops 5` 后把 summary 归档到 Issue。
