# 0013 人员导出写入共用留痕表

Status: accepted（2026-10-18，依 [#105 规格：管理台第一期](https://github.com/bbhl79/natural-enforcement-prj/issues/105)「留痕查阅与导出、`ExportAudit` 停写（#89）」一节；gate① 由 Lei Hu 2026-10-17 22:29 通过）

[0011 认证留痕写入共用表](0011-认证留痕写入共用表.md) 定下认证、配置变更和业务操作共用 `AuditTrail`，但人员导出仍写另一张 `ExportAudit`。监督要查阅和导出全部管理台留痕（#86），留痕分在两张表，查阅就要查两处。2026-10-17 定案（#105）：人员导出改写 `AuditTrail`，`ExportAudit` 只停写，不删表。

这样做是为了让监督只查一张表，同时让已有的导出留痕永久可查（#37、#49）。

本篇部分取代 0011 的三处。0011 正文不改，头部加注「部分被 0013 取代」。下文 0011 的行号按 `e44b980` 计。

## Considered Options

- 人员导出继续写 `ExportAudit`。否决。查阅要拼两张表，导出的留痕也不在监督的查阅范围里。
- 把 `ExportAudit` 的已有行搬进 `AuditTrail`，再删表。否决。删表不在一期（#49、#37），搬迁要改写已经不可改的记录。
- 导出条数写进 `previousValue` 或 `reason`。否决。那两列各有含义，条数要能按数字查。

## Decision

1. **取代 0011「人员导出仍用 `ExportAudit`」**（0011 Consequences 第 1 条）。
   - 人员导出写 `AuditTrail`。操作码 `personnel.profile.export`，只给系统管理。动作词 `personnel.exported`，记成功。
   - 先写留痕，写成功才返回数据。读取与留痕在同一个交互式事务里。留痕写入失败时整体回滚，不返回数据。
   - 被拒的导出（没有该码、超出数据范围、监督）照 0011 写 `authz.denied`，在业务事务回滚后另起事务写入（#119）。
   - 行的所属机构是被导出的机构。资源种类 `org-unit`，资源标识是该机构。
   - `ExportAudit` 只停写：删除应用里的写入路径。表、追加式触发器、G1 白名单条目都保留，schema 注释标为冻结。已有行永久可查。删表不在本篇（#49、#37）。
2. **取代 0011「列」清单**（0011 Consequences 第 2 条）。
   - 追加可空整数列 `itemCount`（库列 `item_count`），记导出条数（Lei Hu 7-7）。不得为负。
   - 只有「带条数的动作」写值，其余动作一律为空。本篇只有 `personnel.exported`。以后的导出动作（如 `audit.exported`，#126）追加进同一张取值表。
   - 导出返回体和留痕里不出现手机号、执法证号、口令。人员导出一行只有人员标识、工号、姓名。
3. **0011:16、0011:31 对引导留痕不适用**。
   - 0011:16 否决了「对不上人员时把机构写成组织树根的 id」；0011:31 定了「没有操作者时，人和机构都空着」。两条都不适用于引导命令写的留痕。
   - 引导命令写的 `bootstrap.root-registered`、`bootstrap.admin-registered` 标明所属机构为根机构（G34）。引导留痕的其余列照 0011 其余规则，由引导命令（#131）实施。
   - 认证、授权拒绝等其余留痕仍照 0011:16、:31。机构空着的行查阅时视同根机构（0011:32）不变。

## Consequences

- 0011 的动作取值表追加 `personnel.exported`（记成功）。这是 0011「以后的图只追加取值」的正常追加，不算取代。
- 留痕设施包的取值表另记「带条数的动作」。带条数的动作缺条数、条数不是非负整数，或别的动作带了条数，写入一律被拒，不写库。
- 人员导出界面不在一期，后端接口保留：`POST /api/admin/personnel/export`，请求体 `{ orgUnitId }`，只导出该机构本身（不含下级）的未停用人员。
- 实施票：[#125](https://github.com/bbhl79/natural-enforcement-prj/issues/125)。查阅与导出（#126）、引导命令（#131）依赖本篇。
