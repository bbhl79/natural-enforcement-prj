# 0012 留痕写入经独立设施包

Status: accepted（2026-10-15）

[0011 认证留痕写入共用表](0011-认证留痕写入共用表.md) 定下认证、配置变更、业务操作共用一张 `AuditTrail`。写入方因此注定跨模块。依赖矩阵里，期限预警不允许依赖身份组织。写端口若放在 identity，期限预警就写不了留痕。2026-10-15 定案：新建留痕设施包 `@natural-enforcement/audit`，与存储、队列设施包同级。各模块经注入令牌 `AUDIT_TRAIL_PORT` 写入。

这样做是为了让所有写入方从第一天起走同一个入口，不在业务图接入时再迁公共出口。

细则在 [规格：用户认证（登录闭环，前后端）](https://github.com/bbhl79/natural-enforcement-prj/issues/91) 的「留痕设施包」一节。本篇只记为什么这样定。

## Considered Options

- 一期放在 identity，期限预警接入时再迁。否决。迁移要改所有写入方的引用，比一开始放对位置更贵。
- 放在 shield。否决。shield 是契约载体，不碰数据库。把写入适配器放进去会改变它的定位。
- 动作与原因取值表放在 shield，与操作码名册并列。否决。取值只有写留痕的一方需要。操作码名册是授权契约，两者不是一回事。

## Consequences

- 包内导出注入令牌、只追加的写入接口、动作与原因的封闭取值表。写入接口没有更新和删除。
- `AuditTrail` 的数据库适配器在包内，只做类型导入，从根类型检查排除。server 负责装配。
- 结构测试新增 `audit-facility-entry`：包外任何代码都不得引用 `auditTrail` 这个 Prisma 委托。结构探针补负例。
- 以后的图追加动作取值时，改这个包的取值表。
