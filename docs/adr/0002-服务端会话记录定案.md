# 0002 服务端会话记录定案

Status: accepted（2026-10-12）

登录闭环需要一种会话：登录成立之后，后续请求如何被认作同一人员。2026-10-12 在无状态 JWT 与服务端记录之间做过对照后，最终选择**服务端记录**：会话落在 PostgreSQL，每次请求由本系统自己的守卫查这行记录。无状态 JWT 在令牌过期前不能结束会话，也做不到空闲 30 分钟由服务端强制退出。等保要求的「结束会话」和「超时自动退出」都要在下一次请求落实。

细则在 [认证：会话与凭据机制选型](https://github.com/bbhl79/natural-enforcement-prj/issues/63) 的最终决议。本篇只记为什么这样定。

## Considered Options

- 无状态 JWT（`@nestjs/jwt`，Bearer）。曾写入决议，对照后由用户否决。已发出的令牌在过期前仍然有效，空闲不会提前结束，也不能按人限 3 段或全系统限 7500 段。
- `express-session` 加 Redis。否决。仓库已锁定 ioredis，connect-redis 10 只接受 node-redis。会话放 Redis 后，结束会话的记录还要另落一处才能审计。
- `@nestjs/authentication` 0.1.0。否决。查证时发布仅数日，pre-1.0，等保基线不采纳。跟踪到 1.x 再评估。
- passport、passport-jwt。否决。passport-jwt 自 2022-12 起无新版。新代码不引入这一系。

## Consequences

- 新增会话记录，触发 g1-model-allowlist。白名单与字段归 [认证：AuthSession 表过 g1-model-allowlist 白名单定案](https://github.com/bbhl79/natural-enforcement-prj/issues/69)，须同时覆盖会话和记住我。记录只失效不删除。
- 不新增 JWT、passport、express-session、CSRF 第三方包。CSRF 用 NestJS 12.1 已有的 `enableCsrfProtection()`。`@nestjs/jwt` 不进版本基线。
- 浏览器侧是 HttpOnly Cookie（`__Host-sid`、`__Host-rm`），要求用户访问全程 HTTPS，由 nginx 终结 TLS。证书来源归 [管理台：运行参数与密钥来源约定](https://github.com/bbhl79/natural-enforcement-prj/issues/80)。
- 每次请求查 PostgreSQL。这是结束会话能在下一次请求生效的代价，不另做缓存层来绕过这次查询。
- 令牌摘要、Cookie 属性、记住我换新秘密由本系统自己实现。漏掉其中一条，会让「下一次请求失效」或「秘密不进脚本」失效。
- 证据：`docs/research/authn-session-stack.md`、`docs/research/password-policy-lockout.md`。
