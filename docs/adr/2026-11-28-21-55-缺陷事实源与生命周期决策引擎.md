## 背景

双轨生命周期需要数据地基：缺陷记录是唯一事实源，注册表只是缓存；生命周期命令
（登记/毕业/退役/重排）要改工作树，但工程基座是**无 bind 烘焙镜像**——容器看不到
宿主工作树，宿主又不装 node 工具链。原型（`prototype/e2e-dualtrack`）已实证一种
形态：容器内纯决策引擎 + tab 行协议 + 宿主侧应用。本票把该形态落到当前基座
（#56–#71：固定快照、不可变绑定、mkdir 锁、per-run 隔离），并定型事实源与注册表语义。

## 决策

1. **事实源分层**：每缺陷一个**入库** JSON（`apps/e2e/defects/DEF-NNNN.json`）是
   生命周期唯一事实源，永不删除；完整性锚在入库记录与 git 历史。目录表达轨道归属
   （`replay/` 零依赖复现脚本、`tests/repro/` 复现轨道、`tests/repro/_drafts/` 草稿区）。
   测试文件头只放缺陷链接，不复制状态。
2. **schema 归 e2e 包**（`apps/e2e/src/defect/schema.ts`），不入 `packages/contracts`：
   生命周期制度不是应用传输契约。形态为 **zod 真判别联合**（`z.discriminatedUnion('engine', …)`，
   六个引擎分支）：机械转写引擎（`fast-check`/`schemathesis`）的 `counterexample`
   必填（毕业直通转写的输入），非机械引擎可选（走草稿区）。覆盖 Spec-e2e §4 全字段；
   `evidence` 用 `strictObject` **只存 URI**（内嵌证据内容字段一律拒绝）；
   `graduation` 含**失败签名**（错误类别 + 断言标识 + 关键语义标记）与**确认记录**
   （确认者/时间/证据快照/令牌六元组）。非法记录 → 退出码 **10**。
3. **门禁分类按被测路径**：`reproducibility.kind` 取 `pure`（纯函数/无外部状态，
   重放 1 次）与 `external-state`（依赖外部状态/并发，独立键空间 ≥3 次），取代原型
   按引擎分类的 `deterministic`/`nondeterministic`（ADR 双轨 §3 口径）。`gate` 由
   report 命令**实测回填**（#109），报告期允许 `attempts=0` 占位；`signatureMatched`
   留位给逐轮签名比对结果。
4. **注册表 = 派生缓存**：`apps/e2e/.registry.json`，`.gitignore` 排除、不入库。
   **始终重建**；与事实源漂移只 `WARN`（+ `registry.rebuilt` 事件 `drift=yes|no`），
   **不作硬门禁**——原型实证「漂移即红」会死锁（校验失败时不重写缓存 → 下次必报
   漂移 → 永远红，哪怕真实违规已修）。缓存只证「派生可重建」。
5. **纯决策引擎 + op 行协议**：生命周期 CLI（`apps/e2e/src/cli.ts`，入口 `main.ts`）
   **不落盘**。宿主树（`defects`/`replay`/`tests` + 既有 `.registry.json`）经 **stdin tar**
   只读进容器 `/tmp/in`；stdout = 协议行，stderr = 人类摘要：
   - `W\t<relpath>\t<base64(utf8)>`（relpath 相对 `apps/e2e`）
   - `D\t<relpath>`
   - `V\t<id数字段>\t<expect:fail|pass>\t<base64>`（校验运行载荷）
   - `END\t<status:ok|error>\t<code>\t<message>`（**每次调用恰一行，最后输出**）
   查询命令（`defect show|list`、`next-id`）的数据行直接走 stdout（非协议行），
   宿主包装为终值 JSON。协议字段内的 tab/换行被拒绝或压平（行协议不可被注入截断）。
6. **宿主侧原子应用**（`devenv/lib/e2e-lifecycle.sh`）：顺序为 **先 V → 再 END → 后 W/D**。
   V 载荷真跑一次判定不符 → **exit 9 零落盘**；END `status=error` → 透传引擎声明的
   码、**零落盘**、原因透出 stderr 与终值 `reason`。W/D 应用前做路径守卫（只允许
   `apps/e2e` 内相对路径，拒 `..`/绝对路径/符号链接分量）、载荷预解码到暂存区、
   既有目标备份；任一步失败**全量还原**（不留半成品）。
7. **`set -e` 吞 END 诊断的收口**（原型坑）：先捕获 CLI 退出码，再判协议——有 END 行
   按协议拒绝（透传码 + 消息）；**无 END 行** = 容器/构建问题，映射 **exit 4** 并把
   子进程码放进终值 `taskRc`（枚举不外逸，比原型直接透传子进程码更严）。
8. **决策引擎跑在 dev 栈 tools 容器**（`compose run --rm -T tools`），不是 e2e 执行器
   镜像：查询/重建不需要浏览器与 per-run 隔离栈，tools 经 workspace 镜像烘焙
   `apps/e2e/dist`（本票给 `apps/e2e` 补 `build`(tsc) 与 `test:unit`(vitest) 脚本，
   turbo build 自动纳入）。执行器镜像只负责 Playwright 真跑（V 载荷经宿主
   `.verify-run/` 生成后 tar 注入，用 `playwright.verify.config.ts`，testDir 在
   repro/explore 树之外）。
9. **生命周期写锁**：per-worktree `e2e-lifecycle-<wt>`，**mkdir 目录锁**
   （`lib/lock.sh lock_acquire`，**不是 flock**——macOS 无 flock，原型实现不搬）。
   写命令从取锁到 op 应用结束持同一把（校验与写入之间无间隙）；与栈锁/租约正交
   （决策命令不做栈变更），无锁序环；查询只读不取锁。跨 worktree 并发由合入时校验
   兜底（撞号 renumber、索引一致性、diff 级）。
10. **取号**：`DEF-NNNN` = 本地 max+1（按 `defects/` 文件名集合，坏记录仍占号——
    记录永不删除），**不填洞**（断号是校验器违规项，#116）。远端叠读经 `devenv gh`
    在**宿主侧** best-effort 取得（容器内无网络凭据，也不得有），以 `--remote-max`
    传入引擎；远端不可用只 WARN 并回退本地。默认远端 ref `dev`，可用 `--remote-ref`
    或 `DEVENV_E2E_NUMBER_REMOTE_REF` 覆盖。
11. **退出码与输出协议**：9（V 判定不符）/10（缺陷不存在或 schema 不符）登记进
    `COMMANDS.md`；7/8 留位给 #116/#109。生命周期**拒绝**路径先发终值事件
    `status:"failed"` 再以该码退出（与 explore 发现同口径，机器可解析）；用法/环境/
    锁冲突走 `die`（无终值事件，沿用既有硬错误口径）。查询数据经全局变量回传，
    **不经函数 stdout**——否则新鲜度 JSONL 事件会被命令替换吞掉，污染结果流。

## 考虑过的选项

- **注册表漂移即红**：拒绝。原型实测死锁（见决策 4）；完整性不在缓存里。
- **决策引擎跑在 e2e 执行器镜像**：拒绝。查询/重建要为此拉起 2.6GB Playwright 镜像
  与 per-run 栈；tools 容器已烘焙源码产物，轻且无需 `devenv up`。
- **宿主直接跑 node/tsc**：拒绝。违背宿主工具链零安装硬不变量。
- **flock 文件锁**：拒绝。macOS 默认无 flock；基座已有 mkdir 锁 + 失效检测 + 持有者诊断。
- **schema 放 `packages/contracts`**：拒绝。Spec-e2e §4 明确归 e2e 包。
- **扁平 schema + 条件校验函数**（原型近似）：拒绝。票面要求真判别联合；按引擎分支
  把「机械引擎必须有反例」变成类型级事实，而不是事后不变量检查。
- **END 只由写命令发**（原型）：改为所有调用恰一行 END，宿主判定统一（查询数据行
  与协议行按首字段区分），避免「rc≠0 但无 END」在查询路径上被误判为容器故障。
- **无 END 崩溃透传子进程码**（原型）：改为映射 4 + `taskRc`，退出码枚举不被绕过。
- **写命令逐行应用、失败即停**（原型）：改为预解码 + 备份 + 失败全量还原，落实
  Spec-e2e §6「任一步失败工作区全量还原」的原子语义。

## 与既有 ADR 的冲突与差距

- 与 [e2e 双轨生命周期机制](2026-11-19-16-48-e2e双轨生命周期机制.md) 的关系：本票
  落地决策 2（事实源分层）、7（schema）、10（命令面与纯引擎 + op 协议）的**地基**；
  决策 3（门禁实测）、4（毕业事务/令牌）、5（失败签名判定）、6（防降级校验）、
  8（复现收敛）、9（回收钉住）分别归 #109/#110/#111/#108/#112/#116/#113，本票不实现。
- **状态机条件不变量不在本票 schema 内**：`reported` 不得带 `graduation` 等状态条件
  字段、索引一致性、注解纪律、编号唯一+连续无洞属校验器（#116，退出码 7）。本票的
  「非法记录 exit 10」指 **schema 层**（字段形态/引擎判别/URI-only/令牌六元组形态）。
- `graduation.failureSignature` 与 `confirmation` 在 schema 中**可选**：expected-fail
  毕业的签名必填性由 #116 校验器判定（ADR 双轨 §6），确认记录由 #111 两段式落账写入。
  本票不实现 graduate，故不预先强制，避免一段式（#110）无法落账。
- **V 载荷真跑需要 per-run 隔离栈**：本票无 graduate 命令，V 路径由离线测试（mock
  执行器）与真跑冒烟脚本（`devenv/test/e2e-lifecycle-smoke.sh`，在真实 run 内驱动
  宿主桥）验证；`devenv e2e` 尚未暴露产生 V 行的命令。
- 命令面新增 `e2e defect next-id` 与 `e2e registry rebuild` 两个**地基入口**（取号与
  派生缓存维护），Spec-e2e §10 的生命周期动词（report/graduate/confirm-fix/retire/
  replay/renumber）仍归后续票；未知子命令一律用法错误 2。

## 后果与边界

- **已验证**：零基础设施单测（mkdtemp 临时树）覆盖 schema/树装载/协议字节格式/
  注册表/取号/CLI；离线编排 56 项覆盖 stdin tar 只读通道、原子应用、V 判定不符
  零落盘、END error 零落盘、无 END 崩溃、路径越界、回滚、写锁冲突、漂移 WARN、
  取号与远端 best-effort；容器真跑见 `.artifacts/106-defect-lifecycle/`。
- **维护面**：`apps/e2e` 现有 `build`/`test:unit` 脚本——workspace 镜像 turbo build
  自动产出 `dist/main.js`（宿主桥依赖该路径）；新增引擎分支必须同时更新判别联合与
  `MECHANICAL_ENGINES`；协议字节格式变更必须同改宿主桥与离线 mock。
- **已声明限制**：
  - 原子应用的回滚不撤销「新建的空目录」（只还原文件内容/存在性）。
  - 注册表漂移在宿主侧按重建前后字节哈希判定，引擎侧 `registryDrifted` 按 JSON
    语义判定（供校验器）；两者对「缓存损坏」都判漂移，语义一致但粒度不同。
  - 远端叠读是 best-effort：网络/授权失败只 WARN，取号仍可用；撞号最终由后合入方
    机械重排（#116），不靠取号时的远端读保证唯一。
  - 缺陷记录夹具**不入仓库**：验收用的临时记录跑完即删（仓库绿地无缺陷记录是合法
    状态，`defect list` 输出空数组）；真实缺陷记录由 #109 登记产生。
  - 决策引擎容器内无网络凭据：任何 GitHub 读写只能由宿主经 `devenv gh` 执行。
- **后续**：#108 replay + 失败签名原语、#109 实测门禁 + report、#110/#111 毕业、
  #112 判定引擎 + `devenv ci`、#113 回收钉住、#116 校验器聚合 + retire/renumber。
