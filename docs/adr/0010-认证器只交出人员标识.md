# 0010 认证器只交出人员标识

Status: accepted（2026-10-15）

一期要预留 IdP／粤政易适配口，同时本地口令登录必须先能用。认证成功若把外部声明抄进身份上下文，组织、角色、数据范围和执法资格就会跟着外部系统走。2026-10-15 定案：认证器只交出本系统人员标识。口令是第一个实现。IdP 是第二个实现位，一期不注册，也不定义字段。

这样做是为了让两条登录路径共用一个端口，并让外部声明停在适配器里面。

细则在 [认证：IdP／粤政易适配口形状（一期仅预留口）](https://github.com/bbhl79/natural-enforcement-prj/issues/72) 的决议。本篇只记为什么这样定。

## Considered Options

- 口令证明带手机号，由认证器自己查人。否决。停用和锁定必须先于验真，编排层仍然要先查一次。
- 认证器放进 shield，或新建 authn 模块。否决。人员与口令散列在 identity。shield 不依赖业务模块。一期没有第二个模块要承载的实现。
- 成功结果携带 IdP 断言。否决。组织、角色、数据范围、执法资格在授权时从本系统当前记录读取，见 [0003 身份上下文在授权时读取](0003-身份上下文在授权时读取.md)。
- 为空的口令散列单列一种账号，或预留外部主体列。否决。空值只表示没有可用的本地口令。将来走 IdP 的人仍是人员表上的同一行。
- 在 `infra/runtime.env` 预列 IdP 密钥，或增加认证方式开关。否决。一期口令实现只读人员行上的散列。供给方式见 [0008 运行参数与密钥分轨供给](0008-运行参数与密钥分轨供给.md)。
- 认证器匹配或拒绝时向模块外发事件，由审计订阅。否决。记住我、停用和锁定都不经过认证器。登录审计若拆成两个来源，同一次登录会有两套写法。

## Consequences

- 浏览器提交手机号和口令。登录编排查出人员标识后填进口令证明，并先判断停用和锁定。查不到人时不调用认证器。
- 口令散列为空，或验真失败，认证器都返回 `rejected`。须改密只发生在散列已经写入、且 `passwordChangedAt` 为空的时候。
- IdP 证明的种类名是 `idp`。一期没有字段，没有实现，调用得到 `unavailable`。登录编排不构造这支。粤政易是这个实现位将来的对接对象。
- 认证器归 identity。其他业务模块不调用它。它不向模块外发事件。登录留痕由登录编排写入。事件名、字段和表已由 [0011 认证留痕写入共用表](0011-认证留痕写入共用表.md) 定案。记住我不经过认证器。
- 协议、字段映射、改密同步、外部主体列和 IdP 密钥名留到真对接。一期不加这些列，也不把密钥写入清单。
- 术语见 `GLOSSARY.md` 的「认证器」。
