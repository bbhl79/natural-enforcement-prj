# 0001 技术栈与版本基线定案

Status: accepted（2026-10-09）

#47（前置地基切片规格）没有锁定基础镜像与依赖版本，兼容性也无从确认（仓库零代码）。2026-10-09 grilling 会话定案：版本基线 = **追新**（定案时各包非 rc/beta/dev 的 latest stable major）、全容器化、宿主引擎统一 Docker + Compose v2，配对全集落 `docs/VERSIONS.md`；兼容性确认采取**双判据**——书面查证（#58/#59，均一手来源、已关闭）加 E1–E7 实测。理由：地基必须先有统一工程底座才能开工，「追新而不追 preview」在生态稳定与原生线红利之间取定案时可辩护的平衡点。

## Considered Options

- 保守基线（会话初稿 majors：PG16 / TS 6.0.2 / Vite 7 / Vitest 3）——用户裁决追新；TS 后因 typescript-eslint peer 墙（R1）实际回到 6.0.2，见后果。
- pg-boss 作队列载体——否决；用户选 BullMQ + Redis（成熟生态），接受多锁一个镜像、多一个 compose 服务、多一个 health 检查对象的代价。
- 文件服务用 MinIO，或本地卷 + 进程内 append-only 目录——均否决；选 RustFS（Apache-2.0；Versioning + Object Lock(WORM) + Legal Hold 有源码级证据），其 1.0 GA 仅三周的年轻度由 E3 实测兜底。
- TS 7.0.2 + Oxlint 替换 typescript-eslint——否决：引入未经研究票查证的组件，违反双判据纪律。
- TS 7.0.2 与 `@typescript/typescript6@6.0.2` 并行（微软官方过渡形态）——否决：ESLint 配置接线多一处未知；地基期优先「无一处未知的第二条 CI 全绿」。
- Podman 作容器运行时（socket 兼容 + docker CLI 契约不变）——评估后用户否决，宿主引擎统一 Docker；引擎选择本属部署形态特化（G7）。

## Consequences

- **TypeScript 钉在 6.0.2**（追新上限被生态整体制约而非单包）：`typescript-eslint@8` peer 上限 `<6.1.0` 拒绝 TS 7，且 TS 7.0 官方不附程序化编译器 API（7.1 才计划补）。升 TS 7.x 属跨 major，回 #60。
- **Prisma 7.10 无原生 PostGIS**：空间列走 `Unsupported("geometry…")` 透传 + `$queryRaw`/ST_ 函数，含必填空间字段的模型禁用 ORM create/update；`CREATE EXTENSION postgis` 必须是迁移历史第一条（维护者官方口径，prisma/prisma#7455）。这两条是刻意的执行纪律，勿当缺陷「修复」；原生路径在 Prisma 8 官方扩展 `@prisma/orm-extension-postgis`（未 GA；其下限 Node 24 / TS 5.9 / ESM-only 与本基线同向）。
- 镜像一律显式 tag + digest、**严禁 `latest`**（`postgis/postgis:latest` 现指 PG17/3.5）；境内镜像加速通道属宿主/CI 环境配置不入库，仓库只写官方名。
- canvas-editor 为预设选型**不进地基**，由首个需出具文书的业务切片自带，G2 不扩大。
- E1–E7 全绿前，兼容性结论只许说「待确认」；#58/#59 关闭仅完成书面腿。
- 证据链：`docs/research/stack-data-compat.md`（#58）、`docs/research/stack-app-compat.md`（#59）、GitHub #47/#58/#59/#60。
