# 0014 根机构守卫

Status: accepted（2026-10-18，依 [#105 规格：管理台第一期](https://github.com/bbhl79/natural-enforcement-prj/issues/105)「人员与登录凭据（#83）」一节的守卫二；gate① 由 Lei Hu 2026-10-17 22:29 通过）

管理台的全部维护动作都按数据范围授权，数据范围从任职机构推导。根机构的系统管理人员是全市数据的最后入口：如果根机构上不再有未停用的系统管理人员，管理台可能失去能维护任何人员的最后一名管理者（故事 42）。所以系统要始终保留至少一名「当前任职在根机构、未停用、持有未停用系统管理角色」的人员。

这样做是为了让管理台不会因连续的人事操作把自己锁死。

## Considered Options

- 不设守卫，靠操作规程约束。否决。停用、摘除角色、调岗三个动作各自合法，组合起来可以把根机构的系统管理清零，事后无法在管理台内恢复，只能改库。
- 给「根机构系统管理」设一个不可摘除的绑定行。否决。人员—角色行只有失效时间没有豁免位，加豁免位要给不可变表开更新例外，代价大于一道判断。
- 在应用内存里记住最后一名根机构系统管理。否决。多个请求并发时内存判断会互相看不见，必须落在库里的同一把锁上。

## Decision

1. **守卫条件**：系统里「当前任职在根机构、未停用、持有未停用系统管理角色」的人员数始终 ≥ 1。四个条件按库里的行判断：当前任职（`endedAt` 为空的任职行指向根机构）、人员未停用、人员—角色行未失效、角色行未失效。
2. **受约束的动作**：停用该人员（#130 实施）、摘除该人员的系统管理角色、把该人员调岗出根机构（两条都由 #129 实施）。动作执行后条件仍满足的，照常放行；会违反条件的，拒绝。
3. **拒绝的返回**：409，`result: invalid-state`，`reason: root-admin-required`，另带一句给人看的可读原因（#105 错误码表「409 可读原因」）。失败留痕写对应动作词加 `outcome=failed`，失败原因取同一个词 `root-admin-required`（`personnel.role-revoked` 或 `personnel.transferred`）。业务行不变。
4. **判断在事务级咨询锁内**：受约束的动作在交互式事务里先取 `pg_advisory_xact_lock`（键由固定字符串 `natural-enforcement:identity:root-guard` 派生，与生产引导的咨询锁不同键，互不阻塞），再数人数，再写业务行，事务结束时释放。两名根机构系统管理并发互相摘除或互相调出时，后取锁的一方在前一方提交后数人，只有一方成功（接缝②有对应测试）。
5. **判断在人员级事务锁之后**：编辑与调岗在读对方当前态之前，先给人员行加 `SELECT ... FOR UPDATE`（`lockPersonnelProfile`），使同一人员上的并发编辑、调岗串行。差异计算与守卫判断都基于锁内的已提交态，避免默认 `READ COMMITTED` 下按陈旧读把角色清零，或经「摘非根人员角色 + 调入根 + 摘原根管理员」交错把根机构系统管理清零。统一锁序：人员行锁 → 机构行锁（`lockOrgUnit`）→ 根守卫咨询锁（`lockRootGuard`）；三条路径都按此序取锁，不产生死锁。目的地清单是只读路径，不取人员锁。接缝②有对应回归测试（双编辑各摘不同角色、编辑与调岗跨同一人员交错）。
6. **不受守卫约束的情形**：目标当前不任职在根机构，或目标不持有系统管理角色时，摘除角色、调岗、停用照常按各自的授权和状态规则判断，不进守卫。守卫一只管的操作（给自己停用、恢复、改角色、改岗位标记、调岗、结束会话）在守卫二之前判断。

## Consequences

- 计数口径落在身份存储接口上（`lockRootGuard`、`countRootGuardAdmins`），判断本身不含业务分支，停用票（#130）接入同一对方法。人员级事务锁 `lockPersonnelProfile` 同落身份存储接口，#130 的停用/恢复也应在它之后判断守卫。
- 摘除角色、调岗出根机构之外，「结束任职而不建新任职」一类将来的动作也要接入本守卫；接入前不得上线。
- 留痕词表为 `personnel.role-revoked`、`personnel.transferred` 各追加失败原因 `root-admin-required`（0011「以后的图只追加取值」的正常追加）。
- 实施票：[#129](https://github.com/bbhl79/natural-enforcement-prj/issues/129)（编辑与调岗）、[#130](https://github.com/bbhl79/natural-enforcement-prj/issues/130)（停用与恢复）。
