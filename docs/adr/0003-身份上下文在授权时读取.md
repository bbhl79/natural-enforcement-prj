# 0003 身份上下文在授权时读取

Status: accepted（2026-10-12）

身份上下文是某次授权所依据的该人员的组织、角色、数据范围与执法资格。2026-10-12 定案：会话只绑定人员标识，这四项在每次授权时从本系统的当前记录读取。勾选记住我时，同一段会话可以从那次认证起一直用到 168 小时。登录时若把四项抄进会话，调岗、改角色或资格变化会在这段时间里继续沿用旧值。

细则在 [认证：身份上下文形状与登录态语义](https://github.com/bbhl79/natural-enforcement-prj/issues/64) 的决议。本篇只记为什么这样定。

## Considered Options

- 登录时把四项抄进会话记录，之后用抄件。否决。记住我会话最长 168 小时，抄件会把旧的数据范围和资格留到这段结束。
- 角色和数据范围当场读，执法资格在登录时抄下。否决。四项分成两条新鲜度规则后，资格变化同样要等到会话结束才看得见。
- 守卫把四项放进 `ActorRef`，同一次请求里的后续授权复用这份。否决。新鲜度会停在请求入口。同一次请求里的多次授权应各自读取当前值。

## Consequences

- 会话记录不加这四列。`AuthSession` 只存人员标识（#69）。
- 每次授权多读人员、当前任职和当前资格。与 [0002 服务端会话记录定案](0002-服务端会话记录定案.md) 一样，不另做缓存层来避开这次读取。
- 生产请求由会话守卫填写 `ActorRef`。`ActorRef` 只有人员标识和已认证。业务代码不改写这两项。
- 认证器只交出本系统人员标识。组织、角色、数据范围、执法资格不从认证器的断言写入身份上下文。
- 资格状态随上下文交出。通用授权不因资格拒绝。哪些操作码要求持证，归 [认证：角色族×操作码矩阵定案](https://github.com/bbhl79/natural-enforcement-prj/issues/71)。状态取值归 [管理台：执法人员资格的登记、有效期与禁作业触发](https://github.com/bbhl79/natural-enforcement-prj/issues/85)。
- 术语见 `GLOSSARY.md` 的「身份上下文」。
