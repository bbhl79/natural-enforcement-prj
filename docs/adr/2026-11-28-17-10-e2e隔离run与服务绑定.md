# e2e 隔离 run：共享基础设施、独立数据面、被测服务自身绑定

## 背景

多 agent 并发是常态。e2e run 需要共享昂贵的基础设施容器（PostGIS/Redis/rustfs），
同时保证数据面与后台处理互不污染；Spec 明确要求**被测 API 与后台 worker 自身**
绑定本 run 资源，反例是"只给测试脚本使用不同名称"——共享服务仍会互相消费任务。

## 决策

1. **两层隔离**：
   - 基础设施容器共享（`db` / `redis` / `rustfs` 由 dev 栈提供）；
   - 每 run 独立数据库、bucket、队列键空间，且由 per-run 的 `api` / `worker` /
     `web` 容器消费（`devenv/compose.e2e.yaml` + 独立 compose 项目
     `<worktree-project>-e2e-<run-id>`）。
2. **per-run external 网络**：devenv 创建 per-run 网络，把共享基础设施容器以
   别名 `db`/`redis`/`rustfs` 接入；per-run 服务名只在本 run 网络内解析，
   不与 dev 栈或其它 run 的 `api`/`web` 别名冲突（基础设施容器同时属于多个网络）。
3. **服务绑定经启动注入**：`DATABASE_URL` / `S3_BUCKET` / `EVIDENCE_QUEUE_NAME` /
   `DATABASE_POOL_MAX`（默认 2/进程）注入 per-run API/worker；worker 只消费本 run
   队列名。业务测试只感知 `E2E_API_BASE_URL` / `E2E_WEB_BASE_URL`（黑盒）；执行器
   另接收本 run 的 S3 坐标，**仅用于隔离 charter 直接核对 bucket 绑定**，不作为
   业务测试访问存储的接口，也不进入公开 HTTP 面。并发 run 数由
   `E2E_MAX_CONCURRENT_RUNS`（默认 4）在登记窗口硬限制（admission 短锁串行化
   "计数→登记"，不串行化 run 本身）。
4. **命名三规则 + 截断哈希**：DB 标识符 `[A-Za-z0-9_]` ≤63；bucket 小写字母数字+
   连字符 3–63、首尾字母数字；BullMQ 队列名禁 `:`（前缀用 `-`）。超长截断后拼
   8 位内容哈希保唯一，不依赖静默截断。run id 为小写 kebab、≤40 字符。
5. **租约而非新锁**：`explore` 运行期持 #61 的 per-worktree 共享栈使用租约；
   `down`/`restart`/`migrate` 等排他意图等待或 exit 6，不会中途拆栈/迁移。
   多个 run 可并行（共享租约可并存）；per-run 资源互不协调。
6. **执行器镜像**：官方 Playwright 镜像（`images.lock` 的 `PLAYWRIGHT_IMAGE`，
   tag+digest/manifest-list）+ 项目 e2e 运行时；`devenv e2e build` 从固定输入快照
   构建并登记不可变 image ID（独立状态文件 `e2e-image.env`，per-worktree
   `e2e-image-<wt>` 锁串行化构建/核对窗口）。**版本严格一致**：镜像 tag 版本 ==
   catalog `@playwright/test`（供应链静态门禁交叉核对）+ 构建期实际安装版本核对。
7. **产物与登记册**：Playwright JSON/HTML/trace/video → per-run 命名卷 →
   `docker cp` 导出宿主 `.artifacts/e2e/<run-id>/`；`run.json` 记录资源坐标、
   per-run 容器清单与镜像绑定。`.devenv-state/e2e-runs/<run-id>.json` 为运行登记册
   （`devenv e2e runs` 可查）；异常退出标记 `aborted`。
8. **探索失败=产出/任务失败**：`devenv explore` 的测试失败以 exit 4 报告，并明确
   "按产出处理：先读证据判读是探索发现还是环境/服务绑定故障，不要未经判读就改
   测试栈"，附产物路径与 per-run 服务日志；环境前置失败仍按 3/4/5 区分。
9. **回收安全**：只删除 e2e 专属前缀且属于本 run 命名空间的资源（库/桶/队列
   键空间）；`delete-bucket` 脚本再次强制 `e2e-` 前缀，开发库/开发 bucket
   永不进入候选集。

## 考虑过的选项

- **每 run 一套完整基础设施容器**：拒绝。违背"基础设施容器共享"，成本与端口/
   资源占用不可接受；也失去共享租约协调的意义。
- **共享 compose 项目 + `compose run` 起 per-run API/worker**：拒绝。服务名
  （`api`/`web`）会注册为共享网络别名，多个 run 之间 DNS 解析会串到别的 run 的
  容器；per-run external 网络从根上消除别名冲突。
- **只让测试脚本用不同库/桶/队列名**：拒绝。Spec 明确此为反例；被测 API/worker
  仍共享一套资源，后台任务会互相消费。
- **e2e run 取排他栈锁**：拒绝。多个 run 必须可并行；运行期只需共享租约。
- **复用 dev 的 api/worker 容器**：拒绝。无法同时绑定两套 run 资源，也无法证明
  后台任务隔离。

## 与既有 ADR 的冲突与差距

- **与 [e2e 双轨生命周期机制](2026-11-19-16-48-e2e双轨生命周期机制.md) 决策 9
  （explore run 默认钉住、环境与产物豁免回收）冲突**：本票只交付隔离运行资源，
  `explore` 当前在运行结束即回收库/桶/队列键空间（findings run 也一样），
  不实现钉住、保留窗口、启动时机会式清理与删除双条件的登记册核对。这些归
  Spec-e2e 回收/钉住后续票；本 ADR 显式记录差距，不声称已满足 §12。
- 删除安全当前由"e2e 专属前缀 + run id 命名空间"保证（`delete-bucket` 再次
  强制前缀），登记册记录只用于可观察与审计；"缺一不删只 WARN"的完整双条件
  随回收票落地。

## 后果与边界

- **已验证**：Windows/WSL2 实机单 run 与双 run 并行（隔离断言 + 后台任务归属）、
  运行期 `down`/`migrate` 被共享租约拒绝（exit 6）、产物导出、库/桶/队列回收。
  原始输出见 `.artifacts/70-e2e-isolation/`。
- **维护面**：新增 workspace 包 `apps/e2e` 必须进入 `workspace.Dockerfile` 两靶
  manifest 清单（否则 lockfile/镜像构建漂移）；升级 Playwright 必须同 PR 改
  catalog 与 `images.lock` 并做 e2e 全量演练。
- **已声明限制**：
  - 基础设施容器被接入多个 per-run 网络；容器重启会丢失这些附加网络连接。
    dev 栈容器重建后需重跑 `devenv up` 再开始 e2e run（既有 run 会因基础设施
    重连失败而暴露为非零退出）。
  - 回收是 best-effort：进程被强制终止（SIGKILL）可能残留库/桶/网络；
    运行登记册标记 `aborted` 供人工复核，自动回收窗口归后续票。
  - 探索失败的"发现 vs 环境故障"归因仍靠证据/日志判读（与 Spec-e2e v1 风险
    一致）；本票不引入失败签名判定。`devenv e2e logs` 只服务该判读，不是生命周期命令。
  - 运行登记册（`.devenv-state/e2e-runs/`）目前永久保留（供审计与 `e2e runs` 查询），
    不随 run 回收删除；保留窗口与清理归回收/钉住后续票。
  - `--run-id` 显式覆盖只校验字符/长度；自动生成的 run id 含 worktree 名段。
    显式 id 不含 worktree 段时不构成跨 worktree 冲突：数据库/Redis/rustfs 容器本身
    已是 per-worktree 资源（#59），run 命名空间落在本 worktree 之内。
  - 并发 run 硬上限取 live 容器 label 计数（admission 短锁串行化检查+登记），
    进程在登记后立即死亡仍可能留下 running 登记项（标 aborted），不影响计数
    正确性（计数看 live 容器，不看登记册）。
  - e2e 执行器镜像按整棵快照哈希复用：与 e2e 无关的源码改动也会触发重建
    （层缓存命中，秒级），以此换取实现简单与来源可核对。
- **后续**：复现轨道接入 CI、生命周期 CLI/失败签名（#72 及 Spec-e2e 后续票）；
  运行回收窗口与钉住。
