# replay 重放与失败签名原语：每轮独立键空间 + 哨兵行约定 + 四档错误类别

## 背景

Spec-e2e §4 要求「任何时点可用 `devenv e2e replay <ID>` 重放已登记缺陷，exit 0 = 复现，
修复后语义自动反转」；§5 要求门禁每轮「从明确前置状态开始、在同一断言处因同一原因
失败」并由机器判定；§7 要求失败签名闭环（错误类别 + 断言标识 + 关键语义标记，不绑定
完整消息文本）。原型（`prototype/e2e-dualtrack`）有 replay 命令与零依赖脚本，但**没有
失败签名模型**——原型 v1 是裸 `test.fail()` + 退出码判定，NOTES-e2e §6.3 明确记录归因
盲区（api 未起时连接错误也算 fail）。本票在 #106 事实源/决策引擎与 #70 per-run 隔离
地基上补齐这两块，并把比对做成 **#109 门禁与 #112 CI 共用的纯函数原语**。

## 决策

1. **replay 起隔离栈复用 #70 per-run 机制，不复活原型单项目 compose/profile**：
   `e2e_derive_names` → 共享栈使用租约（#61）→ `require_services` → `ensure_fresh_workspace`
   → `e2e_build_image` → 每轮 `e2e_admission_begin`（所有权锁 + 并发上限 + 登记册）→
   `e2e_connect_infra` → `e2e_db_purge`/`e2e_migrate` → `e2e_stack_start` → 执行器内跑
   `replayCommand` → 产物导出 + `run.json` → `e2e_teardown` → 登记册终态 → 释放所有权锁。
   编排在**新文件** `devenv/lib/e2e-replay.sh`（减少与 #109/#110 的冲突面），`cmd_e2e`
   只加一条分派臂。
2. **每轮 attempt 一个独立 run id → 独立键空间（强制）**：run id = `<base>-a<k>`。
   replay **会写数据**：同库重复 attempt 撞 `name` 唯一约束（409）会被脚本判成「未复现」，
   即**假语义反转**。每轮独立库/bucket/队列 + 幂等 `DROP FORCE` 重建 + `migrate deploy`
   落实 §5「每次从明确前置状态开始」。轮次间串行（上一轮回收结束才起下一轮）。
3. **退出码语义分档，基础设施错误不算「未复现」**：0 = 全部轮次复现；4 = 未复现
   （含「环境漂移或已修复？」提示）**或**多轮签名不一致/缺失；3 = 基础设施错误
   （脚本 exit 2 或签名 `errorClass=infrastructure`）；10 = 缺陷不存在/记录非法/
   **复现脚本缺失**/`replayCommand` 含 tab 换行（计划阶段即拒，零资源创建）。
   把环境故障与语义反转分开，正是原型 §6.3 归因盲区的收口：判定不再只看退出码。
4. **replay 只读事实源**：不改缺陷记录、不回填门禁（归 #109 report）、不摘注解
   （归 #111 confirm-fix）。因此**不取生命周期写锁** `e2e-lifecycle-<wt>`，与生命周期
   写命令无互斥；运行期锁/租约与 explore 同口径。默认 1 轮（诊断/修复确认），
   `--attempts N` 显式多轮；门禁下限由 `replay-plan` 按被测路径输出供 #109 消费。
5. **replayCommand 失败输出约定（哨兵行）**：脚本零第三方依赖（node 内建 fetch），
   退出码 `0` 复现 / `1` 未复现 / `2` 基础设施错误；**无论复现与否**在 stdout 打一行
   `NE-E2E-SIGNATURE <compact JSON>`，携带 `schemaVersion/assertionId/errorClass/
   semanticMarkers(+outcome 自述)`。复现时标记承载缺陷语义取值（供逐轮比对），
   未复现时承载**实际观测值**（比对不符即语义反转）。多条取最后一条（终态）；
   无标记 → 签名 `null`（**不编造**），单轮仍按退出码判定，多轮无法机器判同一原因 → 4。
   退出码是判定权威，`outcome` 只作证据留痕（两者互为交叉核对）。
6. **失败签名形状（精化 #106 留位字段）**：`{errorClass, assertionId, semanticMarkers}`，
   `semanticMarkers` 由裸字符串数组改为 **`{key,value}` 结构**——比对按 key→value
   **集合**相等（书写顺序无关，`canonicalizeSignature` 规范化），下游无需解析字符串。
   形状权威在 `apps/e2e/src/signature/model.ts`，`defect/schema.ts` 再导出保持既有引用面。
7. **错误类别四档（两档 + 普通断言失败 + 证据不足档）**：`infrastructure`（连接失败/
   超时/服务不健康）→ 判定引擎直接红；`locator`（元素找不到/多命中）→ 红 + 标明
   「需人判断是 UI 改版还是缺陷」；`assertion`（expect 结构可解析）；**`unknown`**
   （证据不足以分类，如测试自身 throw 的自由文本）→ 保守档，**不得据此判绿**。
   增设 `unknown` 是 §7「只把有证据支持的分类当确定事实」的直接落实：把无 expect
   结构的错误硬塞进 `assertion` 会让不同原因的自由文本 throw 产生**相同签名**（假绿）。
   判定顺序即证据优先级：连接级故障码 → 定位失败 → 页面/测试级超时 → expect 结构 →
   unknown（`locator.click: Timeout` 先命中定位档，不被通用超时吞成基础设施）。
   **5xx HTTP 响应本身不判基础设施**——它可能正是被测缺陷。
8. **断言标识是结构身份，不是消息措辞**：Playwright 来源 = `file#describe路径 > 测试标题#断言序号`
   （取**最后一次失败 result**，重试终态为准；不含行号——行号随合法重构漂移）；
   replay 来源 = 脚本作者选定的稳定标识。两来源各自命名空间，比对在**同来源内**进行
   （门禁比 replay 轮次；CI 比毕业 verify-run 证据与本次结果，§7 签名来源口径）。
9. **提取只取结构化证据**：Playwright JSON reporter 的 `error.message` **带 ANSI 颜色码**
   （真实证据实证：原型 DEF-0001 毕业校验运行 `verify-results.json`），提取前必须剥码；
   只取 `matcher` 链与 `Expected:`/`Received:` 单行取值，**自定义消息措辞一律丢弃**。
   据此：合法重构改措辞 → 三要素不变 → 不红；断言弱化（预期状态码 500→400）→
   `expected` 标记不符 → 红。基础设施档取结构化错误码（`net::ERR_*`/errno/固定故障
   短语规范化 token），定位档取 locator 目标表达式与动作。
10. **比对原语 = 纯函数库，本地与 CI 同一份**：`compareSignatures(a,b)` →
    `{matched,reason,differences[]}`（reason 取首个决定性差异维度，differences 列全部
    差异、逐 key 报两侧取值）；`compareSignatureSet(baseline,candidates)` →
    `{allMatched,reason,results[]}`。**任一侧签名缺失 → 不匹配**（无证据不得当同一失败）；
    零轮次 → `allMatched=false`。判定矩阵（绿/红/待判断）归判定引擎（#112），本原语
    只回答「是否同一失败」——边界清晰，避免本票越界建 CI 判定器。
11. **签名引擎载荷走 stdin，不是 #106 的树 tar 通道**：`signature extract --source
    replay|playwright` 与 `signature compare` 经 `compose run --rm -T tools` 执行，
    宿主把载荷文件重定向进 stdin（树 tar 通道留给 `defect`/`registry`/`replay-plan`）。
    协议字节格式与 #106 完全一致（数据行 + `END`），复用其解析助手与「先捕获 rc 再判
    协议」收口（无 END = 容器/构建问题 → 4，子进程码不外逸枚举）。结果恒为**单行紧凑
    JSON**（JSONL 结果流不被多行文档破坏，#106 同口径）。

## 考虑过的选项

- **语义标记用裸字符串数组（#106 留位形态）**：否决——下游要解析字符串才能比对，
  且「预期状态码」与「实际状态码」混在一个串里无法逐维报差异；`{key,value}` 让比对
  与诊断都机械化，代价是精化一个 schema-optional 字段（dev 上尚无入库记录，零迁移）。
- **错误类别只三档（把无 expect 结构的错误归 assertion）**：否决——不同原因的自由
  文本 throw 会得到相同签名（同断言序号 + 空标记），产生假绿；`unknown` 保守档把
  「证据不足」如实表达，判定引擎据此不判绿。
- **签名绑定完整消息文本或其哈希**：否决（Spec-e2e §7 明文）——合法重构改措辞会误红。
- **断言标识用 expect 自定义消息（原型转写模板的 property 字段）**：否决——property
  是消息措辞，重构改文案即漂移；改用结构身份（文件 + 标题路径 + 序号）。
- **断言标识含源码行号**：否决——行号随任何合法编辑漂移，误红率高。
- **replay 默认跑门禁下限轮次（原型口径）**：否决——诊断/修复确认是高频单轮场景，
  多轮成本（每轮一套库/bucket/队列 + 起栈）应由 #109 门禁显式承担；`replay-plan`
  仍输出下限供其消费。
- **多轮复用同一 run（同库多次 attempt）**：否决——唯一约束撞名会伪装成语义反转
  （note 04 §3 坑）；每轮独立键空间是 §5「明确前置状态」的硬要求。
- **宿主 bash 内用 jq 自行比对签名**：否决——判定逻辑会出现第二份实现，违反
  「本地与 CI 同一判定器」；比对一律经引擎原语。
- **签名标记走 stderr**：否决——stderr 是人类诊断通道（输出协议），载荷通道必须
  与诊断分离且可落盘复核（`replay.out`）。

## 后果

- **正面**：诊断与修复确认共用一条命令；环境故障与语义反转分档（原型归因盲区收口）；
  门禁与 CI 共用同一比对原语（判定不漂移）；每轮独立键空间消除假语义反转；
  签名对措辞不敏感、对语义敏感（AC 单测实证）。
- **代价**：多轮重放每轮一套 per-run 资源（起栈 + 迁移 + 回收），成本随轮次线性；
  脚本必须按哨兵行约定打标记才能参与多轮机器判定（旧式裸退出码脚本只能单轮诊断）。
- **已声明差距/局限**：
  - `expected`/`actual` 标记只解析 Playwright 的**单行** `Expected:`/`Received:` 形态；
    `toEqual` 的 diff 块形态只取 `matcher`（粒度较粗）——Spec-e2e 风险节口径：真实
    摩擦出现再收紧签名粒度。
  - `unknown` 档只取 `error.name` 结构证据：同断言处不同原因的自由文本 throw 仍可能
    产生相同签名；由判定引擎「unknown 不得判绿」兜底（#112），不在本票判绿。
  - 跨来源比对（replay 标记 vs Playwright 签名）**不支持**：断言标识命名空间不同。
    门禁比 replay 轮次、CI 比 Playwright 证据，各自同来源（§7 签名来源口径）。
  - `run.json.playwrightExitCode` 字段名沿用既有清单形状，对 `track=replay` 承载
    replayCommand 退出码；权威逐轮记录在 `replay.json.scriptExitCode`（清单形状统一
    归 #111 扩展时一并考虑）。
  - 失败签名误判率仍是保证链中未经原型验证的一环：本票单测 + 两路真跑是首个实测，
    全量演练（#117 验收项 7）继续观测。
  - 回收仍是 best-effort（SIGKILL 留残留 → 登记册 aborted）；保留窗/钉住归 #113。
