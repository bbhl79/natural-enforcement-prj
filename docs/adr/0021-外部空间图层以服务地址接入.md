# 0021 外部空间图层以服务地址接入

Status: accepted（2026-10-24。Lei Hu 签收。承载规格：[#207 规格：线索录入／内业核查／分派／线索中心（统一工作台一期）](https://github.com/bbhl79/natural-enforcement-prj/issues/207) 的协议 J 节）

内业核查要用的七类图层（永久基本农田、生态保护红线、城镇开发边界、耕地、农用地转用审批、建设用地规划许可、供地红线）和街道镇边界，不由本系统落本地副本，也不进参照种子。它们由业务方以空间服务形式提供，系统按服务地址在核查时远程实时查询。

[0016](0016-参照数据随种子只追加写入.md) 给参照数据定的四条（管理台只读、只追加、引用钉版本、改动走评审）对外部图层都不成立：这些图层的内容由服务提供方随时更新，系统既不持有副本也无从追加版本，引用也钉不住某一时点的图层状态。所以外部图层是 0016 的例外范围。0016 正文不改，例外只记在本篇。

可追溯性因此弱于种子方案：事后不能按版本重放当时的图层，只能以核查报告和分析图里固化的事实为准。

服务地址是运行参数（[0008](0008-运行参数与密钥分轨供给.md) 轨道），由部署环境供给。管理台本期不展示、不编辑；二期管理台开放编辑时，并入 [0006](0006-配置类对象共用一套版本与批准.md) 的批准门（满足 [#76](https://github.com/bbhl79/natural-enforcement-prj/issues/76)「配置变更先审批」）。地址不含密钥；服务如需令牌，令牌同样由部署环境注入。

服务不可用、超时、返回不合规，或缺少必要图层时，内业核查明确判失败并置「没跑成」，不生成空报告、不改业务状态，不以空结果冒充成功。缺图层与瞬时故障要分开：前者属确定性错误，不重试；后者按重试口径处理。

## Considered Options

- 把图层落成本地副本并随种子写入。否决。外部图层数据随时在变，本地副本会与源不一致；且要承担图层版本与生效日期管理，超出本期范围。
- 把图层当参照数据，钉版本引用。否决。服务方不提供版本语义，钉不住；0016 的只追加与只读前提也不成立。
- 图层内容直接进业务库。否决。体量与更新频率都不适合业务库承载，也违背「不在本地落图层副本」的业务口径。
- 服务不可用时按「无相交」出报告。否决。那会把「查不到」说成「查过没有」，属以空结果冒充成功。
- 服务地址进管理台可编辑，本期就做。否决。本期管理台无此页；且地址属配置类对象，编辑要走 0006 批准门，二期再并入。

## Consequences

- 本篇是 0016 的例外，不是替代。0016 正文不改，参照种子的承载口径照旧。
- 七类核查图层与街道镇边界的几何不在仓库内，不进种子。
- 核查报告、分析图与运行行保存每层的服务地址（不含任何密钥）、查询时间、返回要素标识与相交要素几何、空间对象版本，作为当时事实的固化依据。初次核查与重跑各用各自运行时的查询结果。
- 街道镇边界服务同时供辖区建议使用。该服务不可用时辖区建议返回空建议，不拦手工分派，但对应验收保持受阻。
- 服务地址与街道到机构的辖区对应的就绪日期，须在相关执行票排期前明确。未就绪时 M4／M5 对应验收保持受阻，不用演示数据替代。
- 术语见 `GLOSSARY.md` 的「内业核查」「核查结果」「街道镇边界」。
