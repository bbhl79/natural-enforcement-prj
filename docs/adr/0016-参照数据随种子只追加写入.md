# 0016 参照数据随种子只追加写入

Status: accepted（2026-10-17。承载方式由 Lei Hu 7-1 定，见 [#78 解答](https://github.com/bbhl79/natural-enforcement-prj/issues/78#issuecomment-6232371728)；所在规格 #105 于 2026-10-17 22:29 过 gate①）

线索来源编码表、案件来源对照表，以及以后的违法类型、依据条款、裁量分档，都是业务录入时供选取的参照数据。它们会改，但改得少，每次改都要有出处、能复查。[0006 配置类对象共用一套版本与批准](0006-配置类对象共用一套版本与批准.md) 把「参照数据入不入那套门」留给了 [#78](https://github.com/bbhl79/natural-enforcement-prj/issues/78)。2026-10-17 定案：参照数据随迁移写入参照种子，所有环境都写，以「业务编码 + 版本」为键，幂等、只追加。管理台只读，改动走代码评审和发布。停用某个编码，就是追加一版标为停用的新版本，不改旧行。

这样做是为了让每一版参照数据都有评审和发布记录，已经录入的业务记录也始终能查回当时用的那一版。

细则在 [规格：管理台第一期](https://github.com/bbhl79/natural-enforcement-prj/issues/105) 的「参照数据（只定承载，#78）」一节和 #78 解答。本篇只记为什么这样定。

## Considered Options

- 走 0006 配置类对象的门（版本、批准、生效日）。否决。没有调用方需要在系统里提交和批准参照数据。代价是市局不能在系统里自行增补违法类型，要等发版，Lei Hu 7-1 已接受。
- 管理台开放直接增删改。否决。改动没有评审记录，也不符合 [#76](https://github.com/bbhl79/natural-enforcement-prj/issues/76) 对配置变更先审批的要求。
- 只在生产环境写，开发测试另用一份夹具。否决。各环境的编码会对不上，测过的选项和生产不是同一套。参照种子与七个角色、操作码名册、允许行同类，所有环境都写（`backend/README.md`「权限与留痕」）。
- 只以编码为键，改名或停用时原地改行。否决。已录入线索指向的那一条会被悄悄改掉，以后调卷对不上当时的名称。
- 停用时删行，或把旧行改成停用。否决。理由同上。记录不物理删除，见 [全局契约：不可篡改与追加式记录](../global-contract-immutability.md)。
- 新增第八个顶层模块承载参照数据。否决。宿主是空间字典模块的参考数据侧（#75 Notes，#78 解答 Q4）。
- 听证申请期一并由本篇承载（#78 解答的原落点）。否决。听证申请期是一条期限规则，Lei Hu 已定期限规则属配置类对象（[#29 评论](https://github.com/bbhl79/natural-enforcement-prj/issues/29#issuecomment-6228766020)），归 [#29](https://github.com/bbhl79/natural-enforcement-prj/issues/29)。#105 第 2 轮拷问 B1 已改掉这个落点。

## Consequences

- **键**：「业务编码 + 版本」是业务唯一键，库里加唯一约束，种子按它判断幂等。每一版另有自己的技术主键（ULID），与业务编码分离（[全局契约：标识、主键与跨域引用关系骨架](../global-contract-identity-references.md) §1 第 1–3 条）。同一编码每改一次（改名、改上级、停用等），就追加一版，版本号加一。
- **只追加**：旧版本不改、不删。表建出来时由库层拒绝 UPDATE 和 DELETE，做法同留痕表（复用 `reject_row_mutation`）。
- **幂等**：参照种子按「业务编码 + 版本」判断，已存在就跳过，重复执行不写新行。库里同一个键的内容与仓库里的种子不一致时，种子报错退出，不覆盖。
- **所有环境写入**：参照数据与角色、操作码名册、允许行同在「参照种子」这一步（现为 `backend/prisma/seed.mjs`），不看 `NODE_ENV`。生产上执行顺序为迁移 → 参照种子 → 引导（#105「生产引导命令」）。
- **管理台只读**：系统里没有参照数据的写动作，不加写操作码。将来出只读界面（P9）时，只读操作码随那个切片加入 `packages/shield` 的名册，允许行归系统管理（#78 解答「补：操作码」）。改动的路径是：改仓库里的种子 → 代码评审 → 发布。
- **停用**：追加一版标为停用的新版本，不改旧行。某个编码的当前版本是版本号最大的那一版；当前版本标为停用的，录入时不再可选。已经引用旧版本的业务记录不受影响。
- **引用**：业务记录引用参照数据时，存所选那一版的技术主键，不存业务编码；一版对应唯一的「编码 + 版本」，引用即钉住版本。展示用的编码、名称随业务记录冻结快照（同一契约 §4 第 1 条「版本化参考数据集 + 冻结快照」）。文书生成时的勾选结果随文书快照固化，对照表以后改版不影响已生成的文书（[#24 对照方案](https://github.com/bbhl79/natural-enforcement-prj/issues/24#issuecomment-6232972124) 打印规则第 6 条）。
- **上下级与出处**：编码的上级显式存「上级编码」，不按编码前缀推断（16、13 挂在 1 下，18、19、20、801–803 挂在 22 下）。每一版带出处（[#24 编码表](https://github.com/bbhl79/natural-enforcement-prj/issues/24#issuecomment-6232970771)「工程落地」）。
- **使用方**：第一个是线索来源编码表（[#24 编码表](https://github.com/bbhl79/natural-enforcement-prj/issues/24#issuecomment-6232970771)，Lei Hu 修订见 [#24 拍板](https://github.com/bbhl79/natural-enforcement-prj/issues/24#issuecomment-6233123369)），管理台不加维护入口。案件来源对照表（线索来源编码 → 文书「案件来源」栏，同两条评论）同为使用方。违法类型清单、依据条款、裁量分档随线索切片和业务地图。法域四类是稳定常量，不是参照数据（#78 解答 Q5）。
- **听证申请期不在本篇**：USER LOCK L1（权威记录见 [#111](https://github.com/bbhl79/natural-enforcement-prj/issues/111)）规定的听证申请期不由本篇承载，归 [#29](https://github.com/bbhl79/natural-enforcement-prj/issues/29)。本篇不建听证申请期参数，也不把它固化成常量。锁的原文不动。
- **本期范围**：只写本篇，不建表、不写种子、不出界面。建表随线索切片，必须过结构测试 `g1-model-allowlist`，按 #69 的做法在同一个 PR 里建表并改白名单（#78 解答 Q2），并按 #47 的流程留记录。
- **宿主**：空间字典模块的参考数据侧。模块自述改为「持有合规规则参考数据，不依赖任何业务模块」。依赖矩阵不变：案件聚合、期限预警对空间字典只读引用（`backend/README.md`）。
- 0006 的 Consequences「参照数据先不入这套门」由本篇收口：参照数据不入配置类对象的门。0006 正文不改。
- 术语见 `GLOSSARY.md` 的「参照数据」「配置类对象」「管理台」。
