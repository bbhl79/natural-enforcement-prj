# 0017 e2e 层与外层 check 的证据分工

Status: accepted（2026-10-19 起草；2026-10-19 22:39 由 Lei Hu 批准，承载规格见 [规格：优化 dev check / CI 效率（e2e 03 瘦身 · 探针单规则化 · 结构测试提速 · 并行拉镜像）](https://github.com/bbhl79/natural-enforcement-prj/issues/168)，该票同日过 gate①）

一次 `./dev check` 跑两套检查：外层总闸跑 lint 全量与三层测试，e2e 层跑用例。两者都取证据，但取的**不是同一份**。本篇把这条分工定下来，让后续任何「少跑一次」的说法都必须先回答「少的是哪一份」。

分工是两条线：

- **命令契约（E7）的 CLI 路径证据只在 e2e 层**（`e2e/cases/03-command-smoke.sh`）。外层 `dev check` 直调内部函数（`cmd_lint`／`cmd_build`／`test_integration`），**不经 CLI**，所以外层跑绿不能证明 `dev lint` 这个命令可用。
- **门禁类检查两层都跑，判红条件相同**：兜底闸（结构测试）、结构测试红探针、容器内 ESLint、依赖漏入库检查、类型检查、前后端编译门。

第二条不等于「同一份证据取两遍」。两层取证的**来源路径不同**：外层走内部函数路径，e2e 层走 CLI 路径；判红条件相同，**证据形态不同**。区分这两者，是本篇存在的理由。

因此「一次 CI 里全量 lint 跑了几遍」这个问题有确定的答法：数的是**同一路径**上的重复，不是跨路径的重复。2026-10-19 定的口径是：外层 1 遍，e2e 层 1 遍（`03` 用例内），`03` 内另有 2 次 `dev lint leak` 子项（判红与转绿各一次）。e2e 层的门禁与外层各跑一遍，是本篇允许的两遍；`03` 用例内原本还有第 3 遍全量 lint，那一遍是**同层内同路径的重复取证**，删掉它不违反本篇。

细则与逐项改造写在规格书票；本篇只记为什么这样分。

## Considered Options

- **把 `03` 用例内的重复全量 `dev lint` 留着**（现状：一次 CI 里 `03` 内跑 3 遍全量 lint）。否决。那 3 遍的判定内容逐字相同，取的是同一份证据。第 2 遍「植入 `node_modules` 后变红」只走到 `lint_leak` 一项就红了，后四项本就不执行；第 3 遍「清除后恢复全绿」的全量五项全绿，已由第 1 遍给出。删掉这 2 遍落在「不重复取证」一侧，不降低任何判红条件。
- **把 CLI 路径证据搬到外层**（让 `dev check` 也走 `dev lint` 这条 CLI）。否决。那要动 CI 调用面与命令面，与 [0004 单一 HTTP 进程与同域入口](0004-单一HTTP进程与同域入口.md)「CI 仍只调用 `./dev check`」冲突，也会把 `check` 的内部函数路径改成 CLI 路径，改变 `check` 本身的语义。
- **把 e2e 层降为纯命令冒烟，不再自证门禁**（`03` 内删掉 `dev lint` 全量与 `dev test integration`）。否决。`dev test e2e` 单独跑就再也证不了兜底闸、红探针、类型检查与编译门；e2e 层的价值不止于「命令能跑」。
- **删 `03` 用例里的 `dev test integration`／`dev build`**。否决。这两处是 E7 证据的唯一出处（命令契约只由 `03` 承担），删掉即削 E7。E7 表述已由 #46／#47／#57 定案，改写需用户单独裁决。
- **另立一份文档专记证据分工**。否决。落点已够：`dev` usage 的 `test` 段、`dev` 的 `test_e2e` 段注释、`03` 用例的 `[说明]` 输出块、本篇。再加一份会制造第二个事实源。仓库无根 README，`docs/agents/` 只放智能体流程文档，`GLOSSARY.md` 不收工程术语。

## Consequences

- **命令契约证据的归属**：E7 的 CLI 路径证据唯一出处是 `e2e/cases/03-command-smoke.sh`。外层 `dev check` 全绿不构成 E7 证据，也不构成 `dev` 任一命令可用的证据。
- **门禁类检查两层各跑一遍**：兜底闸（结构测试）、红探针、容器内 ESLint、依赖漏入库检查、类型检查、前后端编译门。这两遍**判红条件相同、证据形态不同**（内部函数路径 vs CLI 路径）。哪一遍红了都判构建失败。
- **判「重复」要先归路径**：同一路径上的重复取证要消除，跨路径的两遍是分工的必然结果，不在消除之列。「全量 lint 跑了几遍」按路径分别数才有意义。
- **「e2e 层单独跑仍自证门禁」是必须写明的事实**，落三处：`dev` usage 的 `test` 段、`dev` 的 `test_e2e` 段注释、`03` 用例的 `[说明]` 输出块。这三处与本篇同批修改。
- **命令面覆盖不变**：`03` 用例仍覆盖九命令（`test` 命令内跑 unit 与 integration 两层）。瘦身后变化的是 lint 的**内部调用构成**（全量 1 次 + 子项 2 次），不是命令面。
- **`dev test integration`／`dev build` 的 CLI 调用留在 `03` 用例内**。它们与 `dev lint` 全量一起构成 E7 命令契约，删任一项即削 E7。
- **本篇不增删 dev 命令面、不增删 CI 步骤、不改触发策略**。CI 仍只有一步 `./dev check --ci`。
- **本篇不动 `GLOSSARY.md`**。「结构测试＝兜底闸」「结构测试红探针＝负例证据」是工程口径，不属业务词汇。
