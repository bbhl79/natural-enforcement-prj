- 相关：[OpenAPI 契约派生](https://github.com/bbhl79/natural-enforcement-prj/issues/66)、[rustfs 调研](../research/rustfs.md)、[worktree 隔离](2026-11-25-22-30-per-worktree运行资源隔离.md)

## 背景

Spec 要求用户从浏览器上传文件、观察后台处理状态并同源下载相同字节，同时保证
浏览器永远拿不到内部对象存储地址。原型 #11/#12 已用 rustfs + BullMQ 打通上传、
sha256 回写与同源下载，但把 presigned URL 暴露成公开端点 `/evidence/:id/url`，
且 unicode 文件名只在前端临时 `encodeURIComponent`，没有契约级解码失败/长度/
恶意名称处理。本 ADR 固化转正后的边界与实现。

## 决策

1. **浏览器只触同源入口**：公开端点只有
   `POST /evidence`（`application/octet-stream` 原始字节）、`GET /evidence/:id`（状态
   DTO）、`GET /evidence/:id/content`（同源下载）。浏览器响应（上传、记录、下载
   头/体）不包含 bucket、对象键、presigned URL 或任何内部存储地址；DTO 只给相对
   路径 `contentPath`。presigned URL 不注册为公开契约端点。
2. **presigned 仅服务间**：worker 用 presigned GET 经真实 HTTP 从 rustfs 取对象后
   计算 sha256/字节数并回写。它只存在于服务进程/测试进程内，永远不进入 HTTP 响应。
3. **文件名是展示元数据，不是路径/键**：契约包提供
   `encodeOriginalName` / `decodeOriginalName` / `validateOriginalName`，线上约定
   `x-original-name: encodeURIComponent(name)`。入口按码点限 200 字符、wire 值限
   4096 字符；解码失败、路径分隔符/穿越名（`.`/`..`）、C0/C1 控制符（含 NUL/CR/LF）、
   行/段分隔符、双向控制符、纯空白一律 400。对象键只由服务端生成的记录 id 构成
   （`evidence/<id>`），数据库里的 `bucket/objectKey` 不进入 DTO。
4. **后台处理是独立进程**：api 只入队（BullMQ/Redis），`worker` 容器消费并回写
   `pending → ready|failed`；**重试期间保持 `pending`，仅 BullMQ 最后一次尝试失败
   才写 `failed`**（前端只在终态停轮询，避免 failed→ready 时停在失败态）。worker
   心跳写 Redis，compose 健康检查据此判定「已进入消费循环」。浏览器可见的失败文案
   固定（`证据处理失败：无法读取或校验对象`），完整异常只进服务端日志，避免把
   内部地址带进响应。队列名支持 `EVIDENCE_QUEUE_NAME` 注入，为 #70 每 run 键空间预留。
5. **契约面扩展而非旁路**：`ApiContractEndpoint` 支持非 JSON 媒体类型
   （`contentType + zod schema`；binary 用 `z.string().meta({ format: 'binary' })`）、
   `headers`、`pathParams` 与按状态码声明的 `responseHeaders`（下载的
   `Content-Disposition` 也进入契约/OpenAPI）。OpenAPI 完整性检查（#66）对请求体/
   响应媒体类型做精确核对，并逐项核对 query/header/path 参数与响应头的存在性、
   required 与 schema；契约路径的 Express `:id` 与 OpenAPI `{id}` 在核对时归一化。
   文件端点因此与其余 API 同受完整性门禁约束。
6. **每 worktree 存储凭据**：`S3_ACCESS_KEY` / `S3_SECRET_KEY` 随机生成并持久化
   `.devenv-state/storage-credentials.env`（0600，gitignored），rustfs 服务端与
   api/worker/tools 客户端同源注入；rustfs 单节点、`mem_limit: 1g`、无宿主端口，
   数据卷 per-worktree。Redis/rustfs 镜像 tag+manifest-list digest 锁进
   `images.lock`，并纳入供应链静态门禁与 prefetch。
7. **验证入口**：
   - `apps/api/test/evidence.spec.ts` 连真实 PostGIS/Redis/rustfs，覆盖 unicode/emoji
     往返、恶意名称/解码失败/长度、同源下载字节一致、服务间 presigned GET、
     浏览器响应无内部地址；worker 用独立 Nest 上下文与随机队列名，测试自清理。
   - `devenv/test/evidence-ui-smoke.sh` 在 `devenv up` + `devenv web` 后以
     `EVIDENCE_UI_BASE_URL=http://web:4173` 渲染真实 `EvidencePanel`，经 vite preview
     proxy 完成 UI 旅程并自清理。

## 后果与边界

- 上传上限 10 MiB（契约常量）；超大文件走后续文件服务/分片设计时需显式修订，
  不在本票偷偷放宽。
- 可选的 `x-point-id` 关联沿用原型证据模型（非 #69 AC 必需）：只作业务元数据，
  入口校验点位存在性，文件名/对象键边界不受影响。
- 文件名规范化只做拒绝、不做重写；展示层依靠 React 转义，服务端不以文件名寻址。
- 浏览器到 rustfs 的直传（浏览器可达的 presigned）是**明确排除项**：当前网络/地址
  设计下内部存储不可达；若未来引入文件网关，需新增 ADR 并放宽本边界。
- worker 与 api 同镜像、同工作树资源；#70 的每 run 资源绑定将通过 env 注入
  （DB URL/bucket/队列名前缀）扩展，不改变本 ADR 的同源/presigned 边界。
- 集成测试要求栈已 `devenv up`（db/redis/rustfs 健康）；`devenv test` 在服务缺失时
  以 exit 3 明确拒绝，不静默跳过文件证据用例。
