# 0005 权限底座沿用人员与角色权限表

Status: accepted（2026-10-13）

规格《用户认证》v0.1 建议了 `org / user / role / user_role / role_opcode` 五表，并用工号登录。仓库里已经有机构、人员、任职，会话也只绑定人员标识。2026-10-13 定案：不另建用户表，登录主体仍是人员；登录时输入手机号，工号只作业务编号；权限用角色、权限、角色—权限、人员—角色四张表，一人可兼多角，有效权限取并集。监督与办案可以落在同一个人身上，不能监督的范围是某一条线索或某一个案件，不写进这四张表。

细则在 [认证：权限底座数据模型对齐（文档五表 vs 现有 identity 模型）](https://github.com/bbhl79/natural-enforcement-prj/issues/70) 的决议。本篇只记为什么这样定。

## Considered Options

- 按规格五表重做，人员表退役。否决。名称版本和只失效不删除已经落在现有机构、人员、任职上，换一套表会拆掉这套契约。
- 人员表与用户表各存一份。否决。同一次调岗要写两处机构，只改一处时登录读到的机构和办案读到的机构会不一致。
- 用工号或姓名拼音登录。否决。工号是业务编号，不进入登录框。拼音会重名，姓名又有版本，改名后旧拼音还算不算登录标识要另定规则。
- 一个人不能同时拥有监督类角色和办案书写类角色。否决。基层人员会因此闲置：挂了监督就不能办案。限制改到具体线索或案件上：该事项的主办人或协办人不能监督该事项，其他事项仍可监督。
- 把这道同事项限制做成角色上的互斥类。否决。角色表表达的是这个人能做哪类事，不是他在哪一条线索、哪一个案件上回避。

## Consequences

- 不新建 `user` 或第二棵机构树。当前机构仍是人员行上的当前机构，任职历史仍单独保留。停用仍看失效时间，不加在职/停用枚举。
- 登录标识是手机号。有值时全库唯一，空则不能登录。位数与号段不在本篇规定。口令散列继续用已定版的 `argon2` 0.45.1。
- 执法证号与执法证有效期是人员行上的当前值。证号为空或有效期早于今天，即没有执法资格。没有执法资格的人仍可登录。暂扣、注销和换发后的旧证号不在本篇展开。
- 四张新表为 `Role`、`Permission`、`RolePermission`、`PersonnelRole`。一行权限是一条操作码。并集不落库。多个角色共用当前任职机构及其下级，人员—角色行不记机构。主键为 ULID，记录只失效不删除。`g1-model-allowlist` 在建表时加入这四个模型名。人员行上原有的单个角色列在迁移完成后去掉。
- 操作码清单和每个角色包含哪些权限，归 [认证：角色族×操作码矩阵定案（六族×24 操作码）](https://github.com/bbhl79/natural-enforcement-prj/issues/71)。同事项上谁不能监督，归 [监督与办案的职责边界](https://github.com/bbhl79/natural-enforcement-prj/issues/33)。
