# 全局契约：不可篡改与追加式记录的全局保证策略

- **出处**：wayfinder 票 [全局契约：不可篡改与追加式记录的全局保证策略](https://github.com/bbhl79/natural-enforcement-prj/issues/18)（根 Map 契约层）。
- **效力**：子 Map 可以细化字段，不得放宽本文件的任何一条。技术封存（摘要算法、封存产品、密钥保管、保留期限、生产运行参数）不在本文件，见已关闭的可信封存诸票。
- **术语**：以 `GLOSSARY.md` 为准。此处的「批准」只指执法文书经行政审批批准，与配置类对象的「当前生效版本」不是同一个词。

## 1. 一条改正路径

当前内容改成正确值。旧值写入留痕。可以再改回去。再改回去仍写留痕。

留痕写明人员、时间、对象、动作，以及前值或前一版。认证、配置变更、业务操作共用这一种。已经写下的留痕不再改。

法制审核意见、行政审核意见、行政审批意见、会办结论，与线索字段、法域、案由、坐标、文书草稿，都走这条路径。不另写一条并列的更正记录。

## 2. 四个时点

1. **行政审批批准之前**，含已经成文、尚未批准：直接改正，写入留痕。呈批已经送出时，经办人不能改这份执法文书，直到环节回到经办。
2. **批准之后、送达之前**：主办人重新呈批。行政审核和行政审批都通过，才改当前正文。旧文写入留痕。
3. **送达之后**：不改原文。撤销原文书，重新作出，再送达。发起和批准同样走呈批。被撤销的文书留在原案件里，不再作为当前文书。
4. **卷宗定型之后**：走受控重开。同一条呈批通过后才能改，改完再定型，定型通过后才产生新的归档代次，旧代次整份保留。定型就是结案后的归档审批，此后一律走这条呈批，不另设更高角色。监督不能凭这条推进案件主状态。

已经送达并且卷宗已经定型时，第 3 条和第 4 条一起用：撤销、重作、再送达，新文书进入新的归档代次。旧代次和被撤销的文书都留在同一案件里。

定型前的改正不增加归档代次。

## 3. 谁可以改

批准之前，只由该段的写权人改正。承办人不改审核人的意见。法制审核意见由任职机构能覆盖该案、并且持有法制审核角色的人改正。

线索登错时，由当时对这条线索有写权的人追加一条处置记录。线索不删除，不再进入立案。

材料在定型前由主办人标记作废，不物理删除。标识不回收。

误传进入本系统的涉密材料，是唯一的物理删除：管理员删除文件本体，删除写入留痕。

## 4. 配置类对象

批准前可以改同一版正文，旧值写入留痕。已经提交又改了字，这次提交失效，要重新提交才能批准。

批准之后，版本内容不能改。换版、作废、回指旧版本，沿用 [0006 配置类对象共用一套版本与批准](adr/0006-配置类对象共用一套版本与批准.md)。

## 5. 期限

人不能手改到期日，也不能重置已有期限锚。来源日期改正后，旧期限记录保留。系统另生成一条，并写明它取代哪一条。

## 6. 连续性

案件标识不变。不另立新案。已批准或已送达的决定，其事实被新证据推翻时，按第 2 节的时点改正或撤销重作。本条只约束已批准或已送达的决定。批准之前因事实不清作出的退回，按 #28 回到调查，本条不阻止。

## 7. 不承诺的事

合法补充只做到留痕可追溯。系统不承诺这次补充在法律上合法。密码学上「是否被替换」与卷宗完整性的技术封存，不在本文件。
