## 设计假设（issue 里没写、由我推定，共 15 条；v0.4 删去 A16）

- **A1 菜单来源**：假定会话查询会返回本人允许的许可清单（#79 第 3 问选项 B，还没定）。每个菜单项所需的许可写在 `data-requires` 上，许可原文不出现在界面文字里。
- **A2 新许可名**：机构维护和人员维护用了 `org.tree.read`、`org.unit.register|rename|deactivate`、`personnel.read|register|update|deactivate|restore|sessions.end|cert.update` 这些名字。它们是照 wayfinder §3.3、§3.4 的命名建议推的，还没进 `packages/shield`。名册里已经定名的只有 `personnel.locked.*`、`personnel.password.reset`、`audit.admin.*`。
- **A3 界面叫法**：v0.3 起，审计在界面上叫「管理台留痕」，会话类说法用「会话」「结束会话」，与 GLOSSARY 一致；口令沿用「口令」。「登录」只用于指登录这个动作，比如「登录成功」「去登录」。v0.2 用的「管理台操作记录」「结束全部登录」「登录已失效」已全部替换，见「相对 v0.2 的改动」。
- **A4 首屏布局**：首屏放四个入口（机构、人员、被锁人员、管理台留痕），外加一张「需要留意的执法证」统计卡（30 天内到期、已过期、失效、未登记）。v0.4：「暂扣」改「失效」，按 #105 7-3 推出，原文未写。
- **A5 人员列表的列**：列表不显示手机号和执法证号，只显示证件情况。卡片上的手机号默认遮挡，点开才显示完整号码。卡片上显示执法证号。这样做是为了少接触个人信息；#86 只要求留痕，没有要求遮挡。
- **A6 临期阈值**：「临期」定为 30 天内到期。issue 里没有给阈值。
- **A7 P7 的操作文案**：P7 解锁、重设的确认文案、成功文案和两种被拒文案都是我写的。#91 只定了字段，没给这几句话。**v0.4：这 35 条已由 Lei Hu 整体定稿（#105 7-6，2026-10-17 18:09），只改第 17、27、28 条；v0.4 新增的「重设成功」「重设被拒」和口令历史提示为新增、待定稿。**
- **A8 机构停用后一期不提供恢复**：确认框写「一期不提供恢复」（v0.4 按 #105 G13 只改文字，不新增机构恢复操作）。
- **A9 恢复人员（v0.4 按 #105 7-10 重写，G21）**：原任职机构在用时，恢复弹窗只设新的初始口令，不选机构（状态 `restore`）。只有原任职机构已停用时，才在恢复的同一步选新任职机构，可选范围限于操作者数据范围内在用的机构，恢复和调到新机构一并完成（状态 `restoreNewOrg`）。v0.3 的拒绝态 `restoreDenied`、「先调岗」按钮、已停用卡片上的调岗入口均已删除。
- **A10 新建人员的任职机构**：任职机构只能选操作者子树内的机构；调岗的目的地不限（wayfinder §3.4 第 3 问）。
- **A11 结束全部登录不改口令**：确认框写明对方可以用原口令重新登录；怀疑口令泄露时，引导改用「重设初始口令」。
- **A12 导出**：导出格式定为 .xlsx，导出范围等于当前的筛选条件，导出这件事本身也留痕。v0.3 起导出文件名为「管理台留痕_起止日期.xlsx」。
- **A13 上线首日**：首屏横幅按「建机构 → 建人员 → 登记执法证」三步引导。生产引导本身（D5 选项 A，部署者执行命令）不在界面上体现，操作记录里的「建立首个系统管理人员」一条所属机构显示「市局（根机构）」（v0.4 按 #105 G34 改；v0.3 为「无所属机构」）。
- **A14 夹具数据**：工号前缀、人名、机构名、人员标识都是虚构的，只用于示意。
- **A15 被锁列表只放手动「刷新」（v0.2 新增，待定）**：v0.1 称这样做的依据是 #91「前端不轮询」。评审核实，那句只针对会话查询，管不到被锁列表。v0.2 保留手动刷新，改标为待定假设，待 gate① 确认（SCREENS.md G29）。

## 冲突与待定（只标出，不改需求）

1. **主色不一致**：login 代码用 `#1f6b56`，d2d 基线用 `#2D6A5A`。本样板以 login 为准。**v0.4：按 #105 7-5 以登录页代码为准，已符合，未改。**
2. **系统名称不一致**：login 是「广州市规划和自然资源局监督监管与执法协同系统」，d2d 是「广州市自然资源行政执法系统」。本样板以 login 为准。**v0.4：按 #105 7-5 以此为准，已符合，未改。**
3. **login 代码本身有工程词**：LoginPage.tsx 的品牌栏有一句「门禁阻断自动预警」，按本项目的禁用词规范不该出现在用户面前。**v0.2 裁定：另开票处理，这次不动。** 样板 P1、P2 不追加清理。登录页上 #91 定的「本单位管理员」文案，这次也不动。
4. **监督角色的名称**：ADR 0009 叫「监督」，#86 和 ADR 0007 叫「监督评查」。**v0.2 裁定：角色名用「监督」**，与 GLOSSARY 一致。GLOSSARY 已把「监督评查」列为 _Avoid_。
5. **#84 说「文案已定案」，#91 实际只定了字段**：#91 给了被锁列表的字段、登录页的锁定和停用文案，没有管理员操作的文案。P7 的列名逐字用 #91 的字段名，操作文案见 A7，需要确认。另外「当前机构名」作为列名偏工程，但规定不得改，所以照用。**v0.4：35 条已整体定稿（#105 7-6），#84「文案已定案」至此成立（#84 issuecomment-6232660000）；列名照 #91 不变。**
6. **人员标识要不要露给用户**：#91 的定案评论把它列为识别字段，所以 P7 照样显示，是一串 26 位编码，对业务人员不友好。要不要只放在 `data-` 属性里，待定。
7. **执法证旧证号的留痕和审计规则冲突**：#85 和 wayfinder §3.5 建议把旧证号写进 `previousValue`，#86 规定审计不写执法证号。v0.2 以 #86 为准，已删去 P6 里「原证号……会留在变更记录里」一句。旧证号放在哪里，随 #85 定案。
8. **还没定案、样板先按团队建议画的**：
   - D3 机构不移动、#89 无所属机构可见范围：闸①明示；
   - D6 停用、恢复、改角色不审批：待 Lei Hu 定，涉及等保风险；
   - D7 恢复时重设口令：团队自定；原任职机构已停用时在同一步选新机构，v0.4 按 #105 7-10 落实；
   - D8 证件状态：v0.4 按 #105 7-3 只设「有效」「失效」，不设暂扣、注销；
   - #79 第 3 问菜单来源。

   其中 D6 一旦改成双人复核，P6 的确认框要改成「提交待复核」，需要重做。
9. **口令有效期横幅**：#91 有「口令还剩 N 天到期」横幅，属于登录闭环。本样板的壳里没画，需要决定它是否要进 P1。
10. **被锁列表的刷新方式**：v0.1 对这条的引用超出了原文。v0.2 改为设计假设 A15，待 gate① 确认。
11. **改口令页的口令历史提示不是登录页原文（v0.4 新增）**：P2 强制改密页补的「不能与最近 5 次使用过的口令相同」和重复时的拒绝提示，是按 Lei Hu 2026-10-17 18:12 裁定补的，PasswordPage.tsx 和 #91 现有口令策略里都没有这一条。登录页代码和 #91 口令策略要另行跟上，本样板不动仓库代码。
12. **「失效」在 P6 没有单独的卡片状态（v0.4）**：P5 赵磊一行、P3 统计已改为「失效」，但按本次范围只删了 `certSuspended`，没有新增 P6「执法证：失效」状态。是否补，待定。
13. **#105 正文里 7-5 行未标「已定」**：7-3、7-10 行都写了「已定（2026-10-17）」，7-5 只有建议答案。本版按任务指令以登录页代码为准；HTML 本来已符合，未改。
